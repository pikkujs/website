`@pikku/tanstack-start` connects a TanStack Start frontend to a Pikku backend. It gives you two things:

1. **A typed RPC caller** (`makeApi()`, generated by the CLI) for calling Pikku functions from loaders, actions, and components
2. **A Better Auth handler adapter** (`toTanStackStartAuthHandler`) for mounting your Pikku [Better Auth](../middleware/better-auth.md) instance as a Start server route

## Installation

```bash npm2yarn
npm install @pikku/tanstack-start @tanstack/react-start
```

`@pikku/better-auth` and `better-auth` are peer dependencies — you'll already have them if your backend uses Better Auth.

## Typed RPC calls with `makeApi()`

Point the CLI at a shim output file in your Start app via `pikku.config.json`:

```json title="pikku.config.json"
{
  "clientFiles": {
    "rpcWiringsFile": "web/src/pikku-rpc.gen.ts",
    "startServerFnsFile": "web/src/pikku-start.gen.ts"
  }
}
```

Running `npx pikku tanstack-start` (or the full `npx pikku` codegen) generates a `makeApi()` shim that wraps the typed `PikkuRPC` client:

```typescript title="routes/cards.tsx"
import { createFileRoute } from '@tanstack/react-router'
import { makeApi } from '../pikku-start.gen.js'

export const Route = createFileRoute('/cards')({
  loader: () => makeApi().invoke('listCards', {}),
})
```

Every call is fully typed against your backend's RPC map — input and output types come straight from your Pikku function signatures.

:::warning Set VITE_API_URL
The shim reads the API base URL from `import.meta.env.VITE_API_URL` and throws if it's unset. Point it at your Pikku server (e.g. `http://localhost:3000`) — never hardcode a host.
:::

## Mounting Better Auth

`toTanStackStartAuthHandler` turns your auth instance into a Start server-route handler:

```typescript title="routes/api/auth/$.ts"
import { createServerFileRoute } from '@tanstack/react-start/server'
import { toTanStackStartAuthHandler } from '@pikku/tanstack-start'
import { auth } from '../../../auth.js'

const handler = toTanStackStartAuthHandler(auth)

export const ServerRoute = createServerFileRoute('/api/auth/$').methods({
  GET: handler,
  POST: handler,
})
```

If your backend defines auth as a Pikku Better Auth **factory** (`pikkuBetterAuth(...)`), pass the factory plus your config and services creators — the handler resolves them lazily on first request:

```typescript title="routes/api/auth/$.ts"
import { toTanStackStartAuthHandler } from '@pikku/tanstack-start'
import { pikkuAuth } from 'backend/src/auth.js'
import { createConfig, createSingletonServices } from 'backend/src/services.js'

const handler = toTanStackStartAuthHandler(
  pikkuAuth,
  createConfig,
  createSingletonServices
)
```

### Cookies

The package re-exports Better Auth's `tanstackStartCookies` plugin, which makes cookie handling work inside Start's server environment. Add it to your Better Auth instance's plugin list when the auth handler runs inside Start.

## Supported Wirings

- **RPC** — typed function calls over HTTP via the generated `makeApi()` shim
- **HTTP** — any wired route on your Pikku server, called with the generated fetch client

The Pikku backend itself runs wherever you deploy it ([Node HTTP](./node-http-server.md), [Bun](./bun-server.md), serverless, …) — TanStack Start is the frontend integration, not a backend host.
