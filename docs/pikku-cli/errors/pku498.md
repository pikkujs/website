# PKU498: Dynamic Import in Function Body

## Error Message

```
[PKU498] Function 'sendReport' performs a runtime dynamic 'import(...)' in its body. Move the import to the top of the module (static import) or into your services/wireServices setup — function bodies run on every invocation, so a dynamic import there adds latency and defeats bundling/tree-shaking.
```

## What Went Wrong

This is a **warning-level lint**, not a build blocker by default (it only fails the build if you set `lint.functionDynamicImport` to `error`). Your Pikku function's handler body contains a runtime dynamic `import(...)`:

```typescript
export const sendReport = pikkuSessionlessFunc(async ({ logger }) => {
  const { renderPdf } = await import('./pdf-renderer') // ← flagged
  return renderPdf()
})
```

A Pikku function handler runs on **every invocation**. A dynamic `import()` inside it re-enters the module loader on each call, adds latency to the hot path, and makes the dependency invisible to the bundler — so it can't be tree-shaken or included in serverless/edge bundles that only ship the functions they need. Static imports at the top of the module are resolved once, at load time, and bundle cleanly.

Type-only positions like `data: import('node:buffer').Blob` are **not** flagged — those are erased at compile time and never run.

## How to Fix

Hoist the import to the top of the module:

```typescript title="reports.functions.ts"
// ❌ Warns — dynamic import runs on every call
export const sendReport = pikkuSessionlessFunc(async ({ logger }) => {
  const { renderPdf } = await import('./pdf-renderer')
  return renderPdf()
})
```

```typescript title="reports.functions.ts"
// ✅ Correct — static import, resolved once, bundles cleanly
import { renderPdf } from './pdf-renderer'

export const sendReport = pikkuSessionlessFunc(async ({ logger }) => {
  return renderPdf()
})
```

### If you were lazy-loading to avoid a heavy startup cost

Do the expensive setup **once** in your services/`wireServices` factory (which runs at startup, not per-request) and read it from `services` in the function:

```typescript title="services.ts"
// ✅ Allowed — dynamic import in service setup runs once at startup
export const createServices = async (singletonServices) => {
  const { HeavyClient } = await import('heavy-sdk')
  return { ...singletonServices, heavy: new HeavyClient() }
}
```

```typescript title="reports.functions.ts"
export const sendReport = pikkuSessionlessFunc(async ({ heavy }) => {
  return heavy.render()
})
```

Dynamic imports in `services` / `wireServices` setup are intentionally allowed — that code runs once, not on every request.

## Configuring the Rule

The rule defaults to `warn`. Change it in `pikku.config.json`:

```jsonc title="pikku.config.json"
{
  "lint": {
    // "off" | "warn" (default) | "error"
    "functionDynamicImport": "error"
  }
}
```

Set it to `error` to make it a hard build failure, or `off` to silence it entirely.

## Bundling Best Practices

- Put all runtime `import`s at the top of the module — one static import list per file.
- Confine any genuinely dynamic/lazy loading to services/`wireServices` setup, which runs once at startup.
- Keep function bodies pure request-handling logic; move I/O client construction into services so it's shared and tree-shakeable.

## Common Mistakes

```typescript title="wrong.ts"
// ❌ Still warns — a dynamic import anywhere in the body (even nested) is flagged
export const handler = pikkuSessionlessFunc(async ({ logger }) => {
  await Promise.all([import('./a').then((m) => m.run())])
  return { ok: true }
})
```

```typescript title="correct.ts"
// ✅ Correct — hoisted static import
import { run } from './a'

export const handler = pikkuSessionlessFunc(async ({ logger }) => {
  await run()
  return { ok: true }
})
```
