# PKU863: Version Regression or Conflict

## Error Message

```
[PKU863] Version 2 for getTodo is <= latest (3) but not recorded. Possible merge conflict.
```

`pikku versions check` renders it as:

```
✗ getTodo@v2 — version missing from manifest
  Latest recorded version: 3
  Version 2 exists in code but not in versions.pikku.json

  This usually means a merge conflict in versions.pikku.json.
  Resolve the conflict, then run:
  npx pikku versions-update
```

## What Went Wrong

Your code defines a function version that is **at or below** the manifest's recorded `latest`, but the manifest has no entry for it. That combination shouldn't occur in a linear history — recording v3 implies v2 was recorded first. It almost always means `versions.pikku.json` was mangled in a merge: two branches each added a version, and the conflict resolution kept one branch's entries while the code kept both.

## How to Fix

1. **Inspect the manifest for the function** — open `versions.pikku.json`, find the function's entry, and compare its `versions` keys against the versions that exist in code.
2. **Resolve the merge properly** — the correct manifest contains the union of both branches' recorded versions. If one branch's entries were dropped, restore them from `git log -p versions.pikku.json` or the other branch.
3. **Re-record and verify:**

```bash
npx pikku versions update
npx pikku versions check
```

If the versions from both branches collide (both added a v3 with different contracts), you also need to renumber one side — see [PKU850](./pku850.md).

## Contract Versioning Best Practices

- Never resolve `versions.pikku.json` conflicts by "taking ours/theirs" wholesale — merge the `versions` maps.
- Run `pikku versions check` in CI on merge commits, not just PR branches, so bad resolutions are caught immediately.
- Keep manifest updates in the same commit as the version bump they record; it makes conflicts legible.
