# PKU677: Scenario Browser Step Needs Actor

## Error Message

```
[PKU677] Scenario 'checkoutFlow' calls step 'searchesAddons', which declares a browser binding, without an actor. Pass { actor: actors.<name> } so the browser context signs in as that persona.
```

## What Went Wrong

A scenario calls a step that has a `browser` binding, but the step call has no `{ actor: … }` option.

A browser step drives a real page. Which page — and, crucially, *whose session* — comes entirely from the actor: the actor is the signed-in persona whose browser context the step runs in. Without one there's no session, so the step would open an anonymous browser and the scenario would either fail on a login wall or, worse, quietly exercise the logged-out version of the UI while reading as though it tested the logged-in one.

Non-browser steps can legitimately omit the actor; browser steps cannot.

## How to Fix

Pass the actor on the step call:

```typescript title="tests/checkout.feature.ts"
export const checkoutFlow = pikkuScenario<void, { setUp: true }>({
  title: 'A buyer completes checkout',
  tags: ['scenario'],
  func: async (_services, _data, { scenario, actors }) => {
    await scenario.given(
      'opens the catalogue',
      'opensConsolePage',
      { path: '/catalogue' },
      { actor: actors.susan } // ← the browser context signs in as Susan
    )
    await scenario.when(
      'searches for coffee',
      'searchesAddons',
      { query: 'coffee' },
      { actor: actors.susan }
    )
    await scenario.then(
      'sees a result',
      'seesAddonCard',
      { packageName: '@acme/coffee' },
      { actor: actors.susan }
    )
  },
})
```

Every browser step in a flow normally takes the same actor — that's what makes it one user's story. Switching actors mid-flow is legitimate (an admin approving what a buyer submitted) but should be deliberate.

If the actor doesn't exist yet, declare the persona with `definePersonas` — actors are materialised from personas.

### If the step shouldn't be a browser step

A step that only needs to read or write data through the API doesn't need a `browser` binding at all. Give it a plain step body instead, and it can run without an actor.

## Scenario Best Practices

- Guard on the actor at the top of the flow so a misconfigured run fails with a clear message rather than deep inside a step.
- Keep one actor per flow unless the scenario is genuinely about two people interacting.
- Assert through data attributes rather than rendered copy — copy goes through i18n, and reading it back tests your English, not your behaviour.
- Run scenarios with `pikku scenario run <environment>` so actors are seeded and signed in.

## Common Mistakes

```typescript title="wrong.ts"
// ❌ Wrong — browser step with no actor, so there is no session to run in
await scenario.when('searches for coffee', 'searchesAddons', { query: 'coffee' })
```

```typescript title="correct.ts"
// ✅ Correct
await scenario.when(
  'searches for coffee',
  'searchesAddons',
  { query: 'coffee' },
  { actor: actors.susan }
)
```
