# PKU572: Route Query Mismatch

## Error Message

```
[PKU572] Route '/todos' has query parameter(s) [status] not found in function 'listTodos' input type. Input type has: [filter, limit]
```

## What Went Wrong

Your HTTP route declares a query parameter that has no matching property on the wired function's input type. Pikku maps declared query params onto same-named input fields; a name that exists only on the route side would always arrive as `undefined`, so the CLI fails the build instead.

This is the query-string sibling of [PKU571](./pku571.md) (path params).

## How to Fix

Align the query declaration with the function's input type:

```typescript title="todos.wiring.ts"
// ❌ Wrong — input type has 'filter', route declares 'status'
wireHTTPRoutes({
  routes: [
    { method: 'get', route: '/todos', func: listTodos, query: ['status'] },
  ],
})
```

```typescript title="todos.wiring.ts"
// ✅ Correct
wireHTTPRoutes({
  routes: [
    { method: 'get', route: '/todos', func: listTodos, query: ['filter', 'limit'] },
  ],
})
```

Or rename the input property if the query name is the one you want to keep:

```typescript title="todos.functions.ts"
export const listTodos = pikkuFunc<{ status?: string }, Todo[]>(
  async ({ database }, { status }) => database.list('todos', { status })
)
```

## HTTP Route Best Practices

- Declare in `query` only fields that exist on the input type — the input type is the contract, the route just maps onto it.
- Make query-mapped fields optional in the input type; query strings are optional by nature.
- One source of truth: when renaming an input field, update every route that maps it.

## Common Mistakes

```typescript title="wrong.ts"
// ❌ Wrong — pluralization drift after a refactor
query: ['tags']   // input type now has 'tag'
```

```typescript title="correct.ts"
// ✅ Correct
query: ['tag']
```
