# PKU339: Remote Addon Auth Unresolved

## Error Message

For a credential binding:

```
[PKU339] Remote addon 'crm' binds auth.credentialId 'crmOAuth', but no such credential is wired. Available credentials: githubOAuth, slackOAuth
```

For a secret binding:

```
[PKU339] Remote addon 'crm' binds auth.secretId 'CRM_API_KEY', but no such secret is wired. Available secrets: FAKE_CRM_API_KEY, BETTER_AUTH_SECRET
```

## What Went Wrong

A `wireRemoteAddon` declaration binds its auth to a credential or secret **slot in your project**, and that slot doesn't exist.

A remote addon's handlers run on someone else's host, so your project has to say which of *its* credentials or secrets should be presented when it calls them. That binding is a name — `auth: { credentialId: 'crmOAuth' }` or `auth: { secretId: 'CRM_API_KEY' }` — and Pikku resolves it against the credentials and secrets you've declared. An unresolved name would mean the addon is called with no auth at all, failing at runtime in production with a 401 rather than at build time.

Only static bindings are checked. A custom `resolve()` function and a public (omitted) auth surface can't be verified statically and are left to runtime.

## How to Fix

### If you bind a credentialId

Declare the credential, then bind its exact name:

```typescript title="src/crm-credential.ts"
import { defineCredential } from '#pikku/auth'

defineCredential({
  name: 'crmOAuth',
  displayName: 'CRM',
  description: 'OAuth connection to the CRM',
  // …provider config
})
```

```typescript title="wirings/addons.wirings.ts"
wireRemoteAddon({
  name: 'crm',
  package: '@acme/addon-crm',
  auth: { credentialId: 'crmOAuth' },
})
```

### If you bind a secretId

Declare the secret with `defineSecret`, and bind the `name` — not the environment variable:

```typescript title="src/crm-key.secret.ts"
import { defineSecret } from '#pikku/secrets'
import { z } from 'zod'

defineSecret({
  name: 'crmApiKey',
  displayName: 'CRM API Key',
  description: 'Server API key for the CRM',
  secretId: 'CRM_API_KEY',
  schema: z.string(),
})
```

```typescript title="wirings/addons.wirings.ts"
wireRemoteAddon({
  name: 'crm',
  package: '@acme/addon-crm',
  auth: { secretId: 'crmApiKey' },
})
```

The error prints the available names — compare against that list rather than against your environment.

## Remote Addon Best Practices

- Declare the credential or secret first, wire the addon second; the binding is a reference, not a declaration.
- Keep `defineSecret` / `defineCredential` calls in dedicated `*.secret.ts` / `*.credential.ts` files so the available slots are easy to enumerate.
- Use the static `credentialId` / `secretId` form wherever possible — a custom `resolve()` skips this check and moves the failure to production.
- Remember a remote addon package belongs in `devDependencies` (see PKU338).

## Common Mistakes

```typescript title="wrong.ts"
// ❌ Wrong — binds the environment variable name, not the declared secret name
defineSecret({ name: 'crmApiKey', secretId: 'CRM_API_KEY', /* … */ })

wireRemoteAddon({
  name: 'crm',
  package: '@acme/addon-crm',
  auth: { secretId: 'CRM_API_KEY' },
})
```

```typescript title="correct.ts"
// ✅ Correct — binds the declared name
defineSecret({ name: 'crmApiKey', secretId: 'CRM_API_KEY', /* … */ })

wireRemoteAddon({
  name: 'crm',
  package: '@acme/addon-crm',
  auth: { secretId: 'crmApiKey' },
})
```
