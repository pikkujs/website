# PKU574: Exposed Function Has No Gate

## Error Message

```
[PKU574] 3 exposed sessionless functions carry no permission and no addon gate, so they are reachable by anyone through POST /rpc/:rpcName: listInvoices, exportUsers, resetDemoData. Add permissions to the function, set `auth: true` if a session is required after all, gate the whole addon with wireAddon({ auth: true }), or drop `expose: true` if they were not meant to be callable from outside.
```

This is a **warning**. It prints on every build, but only fails the build with `--fail-on-warn`.

## What Went Wrong

A function is marked `expose: true` (callable from outside over `POST /rpc/:rpcName`), is sessionless (`auth: false`), and has no `permissions` and no addon-level gate. Nothing stands between an anonymous request on the internet and that function's body.

Sessionless is the given here, not the defect — plenty of functions legitimately serve anonymous callers. The finding is that *nothing else* narrows who may call them. The audit exists because exposure, auth and permissions are set in three different places, and it's easy for a function to end up public through the combination of three individually reasonable decisions.

Note what the remedy list deliberately omits: `scopes`. `verifyScopes` fails closed on a session that doesn't exist, so adding scopes to a sessionless function turns every public request into a `MissingScopeError` rather than gating anything.

## How to Fix

Pick whichever is actually true of the function:

### If it should require a signed-in user

```typescript title="src/functions/invoices.functions.ts"
export const listInvoices = pikkuFunc({
  expose: true,
  auth: true, // a session is required
  func: async ({ kysely }, _data, { session }) => { /* … */ },
})
```

### If anonymous callers are fine but not *all* of them

Express the rule as a `permissions` entry — never as an `if` inside the body:

```typescript title="src/functions/demo.functions.ts"
export const resetDemoData = pikkuFunc({
  expose: true,
  permissions: { isDemoEnvironment },
  func: async ({ kysely }) => { /* … */ },
})
```

### If every function in the addon needs the same gate

```typescript title="wirings/addons.wirings.ts"
wireAddon({ name: 'admin', package: '@acme/addon-admin', auth: true })
```

### If it was never meant to be callable from outside

Drop the exposure — this is the right answer more often than people expect:

```typescript
export const listInvoices = pikkuFunc({
  // no `expose` — internal RPC only
  func: async ({ kysely }, _data, { session }) => { /* … */ },
})
```

## Exposure Best Practices

- Treat `expose: true` as a deployment decision, not a convenience: it publishes an internet-reachable endpoint.
- Default to `auth: true` and relax deliberately, rather than the reverse.
- Keep authorization in the `permissions` field so it is visible to the audit — a check inside the function body is invisible to it.
- Re-read this warning after every refactor that moves functions between addons; an addon-level gate doesn't travel with the function.

## Common Mistakes

```typescript title="wrong.ts"
// ❌ Wrong — the check is real but invisible to the audit, and runs after the call is accepted
export const exportUsers = pikkuFunc({
  expose: true,
  func: async ({ kysely }, data) => {
    if (data.apiKey !== 'hunter2') throw new Error('nope')
    return kysely.selectFrom('user').selectAll().execute()
  },
})
```

```typescript title="correct.ts"
// ✅ Correct — gated declaratively, before the body runs
export const exportUsers = pikkuFunc({
  expose: true,
  auth: true,
  permissions: { isAdmin },
  func: async ({ kysely }) => {
    return kysely.selectFrom('user').selectAll().execute()
  },
})
```
