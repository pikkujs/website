# PKU481: JSON Column Untyped

## Error Message

```
[PKU481] Column "public.users.metadata" is jsonb and will be typed as `unknown` — JSON/JSONB columns need a concrete TypeScript type. In db/annotations.ts add: "metadata": { kind: 'json', tsType: 'YourType' }.
```

## What Went Wrong

A `json` or `jsonb` column carries no inherent TypeScript shape — the database only knows it's "some JSON". Without a concrete type, Pikku has to fall back to `unknown`, which means every place that reads `users.metadata` loses type-safety: no autocomplete, no field checking, and casts creeping in across your codebase.

This is a **warning**, not a blocker (it only fails the build under `--fail-on-warn`). Pikku emits it so you — or an AI assistant — can give the column a real type instead of quietly shipping `unknown` everywhere. If you genuinely want an untyped column, an explicit `tsType: 'unknown'` (or `'any'`) is accepted as an acknowledgement, though it's still discouraged.

## How to Fix

Give the column a concrete `tsType` in `db/annotations.ts` — the hand-editable annotations file — alongside `kind: 'json'`.

```typescript title="db/annotations.ts"
// ❌ Wrong — jsonb column with no tsType degrades to `unknown`
export const annotations = {
  'public.users': {
    // metadata resolves to `unknown` at every call site
  },
}
```

```typescript title="db/annotations.ts"
// ✅ Correct — a concrete type flows through the generated Kysely types
export const annotations = {
  'public.users': {
    metadata: { kind: 'json', tsType: 'UserMetadata' },
  },
}
```

Make sure `UserMetadata` resolves where the generated types are used (export it from a module the generated code can import). Then regenerate:

```bash
pikku db migrate
```

## Database Schema Best Practices

- Every `json`/`jsonb` column should have a declared `tsType` — treat "untyped JSON" as a bug, not a shortcut.
- Reuse a shared, named interface for the column's shape so reads and writes agree on the same contract.
- If a column truly holds arbitrary data, set `tsType: 'unknown'` deliberately so the choice is explicit and reviewable — don't leave it to the fallback.

## Common Mistakes

Editing the generated schema instead of the annotations file. `db/schema.d.ts` is regenerated on every `pikku db migrate`, so a hand-typed shape there is silently overwritten.

```typescript title="db/schema.d.ts"
// ❌ Wrong — hand-editing the generated file; wiped on the next migrate
export interface UsersTable {
  metadata: UserMetadata // manually typed here — will not survive
}
```

```typescript title="db/annotations.ts"
// ✅ Correct — declare the type in the hand-editable annotations file
export const annotations = {
  'public.users': {
    metadata: { kind: 'json', tsType: 'UserMetadata' },
  },
}
```
