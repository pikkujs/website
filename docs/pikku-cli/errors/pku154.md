# PKU154: Agent Tool Missing Description

## Error Message

```
[PKU154] AI agent 'support-agent' uses tool 'listInvoices', which has no description. An agent tool's description is what the model is told it does; without one it is offered the tool under its own name. Add a 'description' to 'listInvoices'.
```

If the function has a `title` but no `description`, the message adds:

```
(a 'title' does not count — it labels the tool, it does not explain it)
```

## What Went Wrong

A function offered to an AI agent as a tool has no `description`. This check runs under strict metadata mode.

A tool's description is the *only* thing the model reads when deciding whether to call it. Without one, the model sees nothing but the identifier — `listInvoices` — and has to guess from the name alone what it does, what it costs, and when it's appropriate. That produces the two failure modes you'd expect: a tool the agent never reaches for, and a tool it reaches for at the wrong moment.

A `title` doesn't satisfy this. A title is a human-facing label for consoles and docs; a description is instructions for the model.

## How to Fix

Add a `description` to the function itself, not to the agent:

```typescript title="src/functions/invoices.functions.ts"
export const listInvoices = pikkuFunc({
  title: 'List invoices',
  description:
    'Lists the signed-in user\'s invoices, most recent first. Use when the user asks about billing history, a specific charge, or an unpaid balance. Returns at most 50 invoices.',
  func: async ({ kysely }, _data, { session }) => {
    return kysely
      .selectFrom('invoice')
      .where('userId', '=', session.userId)
      .selectAll()
      .execute()
  },
})
```

For an addon tool you don't own, the description has to come from the addon — update and rebuild the addon, or open an issue against it. If you can't, drop the tool from the agent rather than shipping an unexplained one.

To turn this check off for a project that isn't ready for it, disable strict metadata in `pikku.config.json`. Prefer fixing the descriptions: this check exists because undescribed tools degrade agent behaviour silently.

## AI Agent Best Practices

- Write the description for the model, not for a changelog: say *what it does*, *when to use it*, and *what it returns*.
- Mention the constraints the model can't infer — pagination limits, side effects, cost, irreversibility.
- Describe destructive tools defensively ("permanently deletes; only call after the user has explicitly confirmed").
- Keep `title` short and human-facing; keep `description` complete and model-facing.

## Common Mistakes

```typescript title="wrong.ts"
// ❌ Wrong — a title is not a description
export const deleteAccount = pikkuFunc({
  title: 'Delete account',
  func: async ({ kysely }, _data, { session }) => { /* … */ },
})
```

```typescript title="correct.ts"
// ✅ Correct — the model is told what it is and when it applies
export const deleteAccount = pikkuFunc({
  title: 'Delete account',
  description:
    'Permanently deletes the signed-in user\'s account and all their data. This cannot be undone. Only call after the user has explicitly confirmed deletion in their own words.',
  func: async ({ kysely }, _data, { session }) => { /* … */ },
})
```
