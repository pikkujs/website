# PKU485: Default Schema Name Collision

## Error Message

```
[PKU485] Dropping the "public" qualifier would make "audit.events" and "public.events" both "events". "audit.events" keeps its qualifier.
```

## What Went Wrong

Tables in your default schema are exposed under their bare name, so `public.users` becomes `users` in the generated types — the qualifier is noise when there is only one candidate. Here there is more than one: two schemas each hold a table that would collapse to the same bare name.

Rather than let one shadow the other, Pikku keeps the qualifier on the table that is *not* in the default schema and tells you which one that was. Nothing is lost; the name is just longer than you might expect.

This is a **warning**, not a blocker (it only fails the build under `--fail-on-warn`). Your types are correct either way — this explains why one of them reads `auditEvents` rather than `events`.

## How to Fix

Often the right response is nothing at all: the qualifier is doing its job, and the generated name is unambiguous.

If the longer name bothers you, remove the ambiguity at its source — rename one of the tables through a forward migration:

```sql title="db/migrations/0008-rename-audit-events.sql"
ALTER TABLE audit.events RENAME TO audit_entries;
```

Or point `defaultSchema` at whichever schema you actually want unqualified:

```json title="pikku.config.json"
{
  "db": {
    "defaultSchema": "public"
  }
}
```

Then regenerate:

```bash
pikku db migrate
```

## Database Schema Best Practices

- Keep table names unique across schemas when those schemas share a generated namespace — it keeps the generated names short and stable.
- Set `defaultSchema` to the schema your application actually owns, so its tables get the bare names and everything else stays qualified.
- Treat a new collision warning as a signal: a table name that just became ambiguous is one a reader can now misattribute.

## Common Mistakes

Chasing the warning by hand-editing the generated schema so both tables get the bare name. `db/schema.d.ts` is regenerated on every `pikku db migrate`, the edit is lost, and until it is you have two types racing for one name.

```typescript title="db/schema.d.ts"
// ❌ Wrong — hand-editing a generated file to force the short name
export interface Events { /* which table is this? */ }
```

```sql title="db/migrations/0008-rename-audit-events.sql"
-- ✅ Correct — remove the ambiguity in the schema, then regenerate
ALTER TABLE audit.events RENAME TO audit_entries;
```
