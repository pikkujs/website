# PKU529: Dynamic Step Name

## Error Message

```
[PKU529] Workflow 'myWorkflow' contains a step whose name cannot be
statically determined. Step names must be string literals or deterministic
template expressions.
```

## What Went Wrong

Pikku's inspector reads your workflow source statically at build time to extract the step graph. For this to work, step names passed to `workflow.do()` and `workflow.sleep()` must be resolvable without executing code.

When a step name comes from a function call, an imported variable, or a `Math.random()`-style expression, the inspector can't extract it — and more importantly, workflow replay breaks at runtime, since the step name used on the first run must exactly match what's produced on every subsequent replay.

```typescript
// ❌ Function call — can't be resolved statically, breaks replay
await workflow.do(getStepName(), 'myRpc', input.data)

// ❌ External variable — value unknown at build time
import { STEP } from './constants'
await workflow.do(STEP, 'myRpc', input.data)

// ❌ Non-deterministic value — different on every replay
await workflow.do(`step-${Math.random()}`, 'myRpc', input.data)
```

## How to Fix

Use string literals directly, or template literals where the interpolated values come from the loop variable itself (which is always deterministic):

```typescript
// ✅ String literal
await workflow.do('enrich-user', 'enrichUserRpc', input)

// ✅ Template literal over a loop variable — deterministic, fine
for (const event of input.events) {
  await workflow.do(`process-event-${event.id}`, 'processEventRpc', { event })
}

// ✅ Template literal over a stable input field
await workflow.do(`notify-${input.userId}`, 'sendNotificationRpc', input)
```

## Why Step Names Must Be Deterministic

Pikku workflows are durable: when a step completes (or the process restarts), the engine replays the workflow function from the top, skipping already-completed steps by matching the step name against the persisted run history. If the step name changes between the original run and the replay, the engine can't find the completed step and will execute it again — causing duplicate side effects or infinite loops.

This means step names must produce the same string on every replay for a given set of inputs. String literals always satisfy this. Template literals over input fields or loop variables do too, as long as the inputs themselves are deterministic.
