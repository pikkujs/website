# PKU341: Addon MCP Function Not Found

## Error Message

```
[PKU341] wireAddon('issues') lists 'listIssuess' under mcp, but @acme/addon-issues publishes no such function.
```

## What Went Wrong

`wireAddon`'s `mcp` option was given a list of function names, and one of them isn't a function that addon publishes. Usually it's a typo, or a name that was renamed in the addon and never updated here.

The list is the tool menu this deployment offers an MCP client, so a name that resolves to nothing is a tool you believe you're offering and never are. Nothing fails at runtime — the model is simply handed a shorter menu than the wiring reads as, and the missing capability shows up as the agent declining work it looks equipped for.

In a project generated by `pikku all`, the same mistake is also a type error: the generated `#pikku/addon` types `mcp` against the names each installed addon publishes, and TypeScript will usually suggest the name you meant. This build-time check exists for the paths that type gate doesn't cover — a wiring written before generation has run, or a project that isn't type-checked in CI.

## How to Fix

Check the names against what the addon actually publishes. Its function metadata is generated into the package:

```bash
cat node_modules/@acme/addon-issues/.pikku/function/pikku-functions-meta.gen.json | jq 'keys'
```

Then fix the list:

```typescript title="wirings/addons.wirings.ts"
// ❌ Wrong — 'listIssuess' isn't a function the addon publishes
wireAddon({
  name: 'issues',
  package: '@acme/addon-issues',
  mcp: ['listIssuess', 'searchIssues'],
})
```

```typescript title="wirings/addons.wirings.ts"
// ✅ Correct
wireAddon({
  name: 'issues',
  package: '@acme/addon-issues',
  mcp: ['listIssues', 'searchIssues'],
})
```

If you wanted whatever the addon considers tool-shaped rather than a menu of your own, use `true` and let the addon decide:

```typescript
wireAddon({ name: 'issues', package: '@acme/addon-issues', mcp: true })
```

If the addon renamed the function, bump the addon and regenerate:

```bash
npm install @acme/addon-issues@latest
npx pikku prebuild
```

## Best Practices

- Name the tools you mean rather than reaching for `mcp: true` — the menu a model sees is an authorization surface, and the shorter it is the less there is to misuse.
- Keep the list in the same change as the addon upgrade that renames a function; the type error and this one both point at it, but only if generation has run.
- `mcp: []` is a valid answer: it installs the addon and offers no tools at all, which is what you want when its functions are reached only through your own wirings.
- The list may name a function the addon never declared `mcp: true`. That's deliberate — the addon declares what it thinks is tool-shaped, the app installing it decides what a model sees.
