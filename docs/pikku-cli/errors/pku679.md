# PKU679: Scenario Not Extractable

## Error Message

```
[PKU679] Scenario 'checkoutFlow' could not be extracted, so none of its steps were recorded and it would run as an empty scenario:
Unsupported statement: try/catch is not allowed in the workflow DSL
```

The text after the colon is the specific rule that was broken.

## What Went Wrong

A `pikkuScenario` body doesn't conform to the restricted DSL that scenarios are read with, so the CLI could not extract its steps.

This is a hard error rather than a warning because of what the fallback would do. Pikku's fallback extractor understands `do` and `sleep`, but not the scenario vocabulary — `scenario.given` / `when` / `then` and `pikkuScenarioStep` calls. A scenario that fell through to it would register with **zero steps**: it would run, pass, and report green while testing nothing at all. A vacuously-passing test is worse than a failing build.

Common causes:

- `try` / `catch` in the body — not supported in the DSL by design; use the `onError` step option instead
- A computed step target (see [PKU678](./pku678.md))
- Steps issued from inside a callback (`.map(async …)`, `forEach`) rather than from the body
- Conditionals or loops built from values the CLI can't resolve statically

## How to Fix

Read the reason printed after the colon — it names the exact construct — and rewrite that part in the DSL.

### `try` / `catch`

```typescript title="fixed.ts"
// ✅ Correct — failure handling as a step option, not a language construct
await scenario.when(
  'submits the order',
  'submitOrder',
  { sku: 'A1' },
  { actor: actors.susan, onError: 'continue' }
)
```

### Steps inside a callback

```typescript title="fixed.ts"
// ✅ Correct — a plain for..of in the body, so each step is visible to extraction
for (const item of ITEMS) {
  await scenario.when(
    `adds ${item.label}`,
    'addToCart',
    { sku: item.sku },
    { actor: actors.susan }
  )
}
```

### Computed targets

Keep the target a string literal and vary the data — see [PKU678](./pku678.md).

After rewriting, regenerate and confirm the scenario now reports its steps:

```bash
npx pikku prebuild
```

## Scenario Best Practices

- Write the body as a flat ladder of `given` / `when` / `then` calls; anything cleverer usually isn't extractable.
- Keep logic in the step functions, not in the scenario — the scenario is a script, not a program.
- Use `for..of` rather than `.map`/`.forEach` so awaited steps stay in the body.
- Check the generated scenario has the step count you expect; zero steps is the symptom this error prevents shipping.

## Common Mistakes

```typescript title="wrong.ts"
// ❌ Wrong — try/catch is not part of the DSL, so nothing extracts
export const checkoutFlow = pikkuScenario({
  func: async (_services, _data, { scenario, actors }) => {
    try {
      await scenario.when('submits', 'submitOrder', {}, { actor: actors.susan })
    } catch {
      await scenario.then('sees an error', 'seesError', {}, { actor: actors.susan })
    }
  },
})
```

```typescript title="correct.ts"
// ✅ Correct — the failure path is a step option and an explicit assertion
export const checkoutFlow = pikkuScenario({
  func: async (_services, _data, { scenario, actors }) => {
    await scenario.when(
      'submits an invalid order',
      'submitOrder',
      { sku: '' },
      { actor: actors.susan, onError: 'continue' }
    )
    await scenario.then(
      'sees a validation error',
      'seesError',
      { message: 'sku required' },
      { actor: actors.susan }
    )
  },
})
```
