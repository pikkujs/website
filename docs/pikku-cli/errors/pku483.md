# PKU483: Secret Column Stored in the Clear

## Error Message

```
[PKU483] Column "public.users.api_token" is classified secret but stored in the clear. Declare how it is held in db/annotations.ts — form: 'hashed' | 'wrapped' | 'sealed' — or form: 'plain' to state that reading the row is meant to yield a usable credential.
```

## What Went Wrong

The column is classified `secret`, so Pikku already keeps it out of API responses. But classification says *who may see it*, not *how it is stored* — and those are different questions. A secret held as readable text is one database read away from being usable by whoever performed the read: a backup, a replica, a support query, a leaked dump.

`form` is the second axis. It records how the value is held at rest, and Pikku will not guess it for you.

This is a **warning**, not a blocker (it only fails the build under `--fail-on-warn`). Every project that predates `form` has such columns, and a hard error would break all of them on the next migrate.

## How to Fix

Say how the column is held, in `db/annotations.ts`:

| `form`      | Meaning                                                              |
| ----------- | -------------------------------------------------------------------- |
| `'hashed'`  | A one-way digest. You can verify a candidate; you cannot recover it.  |
| `'wrapped'` | Encrypted under a key held elsewhere. Recoverable only with that key. |
| `'sealed'`  | Encrypted to a recipient. The database cannot open it at all.         |
| `'plain'`   | Deliberately readable — reading the row yields a usable credential.   |

```typescript title="db/annotations.ts"
// ❌ Wrong — classified but silent about storage
export const annotations = {
  'public.users': {
    password: { classification: 'secret' },
  },
}
```

```typescript title="db/annotations.ts"
// ✅ Correct — a password is verified, never recovered
export const annotations = {
  'public.users': {
    password: { classification: 'secret', form: 'hashed' },
  },
}
```

`form: 'plain'` is a real answer, not a way to silence the warning. Some credentials genuinely must be replayable — an outbound API token you have to send verbatim cannot be hashed. Declaring `'plain'` states that intent and ends the warning:

```typescript title="db/annotations.ts"
// ✅ Correct — a replayable token, acknowledged as such
export const annotations = {
  'public.integrations': {
    apiToken: { classification: 'secret', form: 'plain' },
  },
}
```

Then regenerate:

```bash
pikku db migrate
```

## Database Schema Best Practices

- Treat classification and `form` as separate decisions: one governs exposure, the other storage.
- Prefer `'hashed'` whenever you only ever need to *check* a value rather than *use* it.
- Reach for `'plain'` only when the credential must leave your system verbatim — and let the annotation record that it was a decision.
- Turn on `--fail-on-warn` once your columns are annotated, so a newly added secret cannot slip in unclassified.

## Common Mistakes

Hashing in application code but leaving the annotation off. The annotation is what the generated types, the audit command, and the next reader all consult — the code alone tells them nothing.

```typescript title="db/annotations.ts"
// ❌ Wrong — the value is hashed at the call site, but nothing records that
export const annotations = {
  'public.users': {
    password: { classification: 'secret' },
  },
}
```

```typescript title="db/annotations.ts"
// ✅ Correct — the schema states how the column is held
export const annotations = {
  'public.users': {
    password: { classification: 'secret', form: 'hashed' },
  },
}
```
