# PKU643: Complex Workflow Not Allowed

## Error Message

```
[PKU643] 'pikkuWorkflowComplexFunc' is used here, but this project has not enabled complex workflows. Their inline steps cannot be serialized, so they are absent from the workflow graph and cannot be replayed or migrated across a definition change. Express the workflow with pikkuWorkflowFunc and the step DSL, or set `allow: { complexWorkflows: true }` in pikku.config.json if the project accepts that trade.
```

## What Went Wrong

A workflow is declared with `pikkuWorkflowComplexFunc`, and the project hasn't opted into complex workflows.

The difference between the two wrappers is what the CLI can *see*. `pikkuWorkflowFunc` uses the step DSL, so every step is extracted statically into the workflow graph: it can be drawn as a graph, replayed after a crash, and migrated when the definition changes. `pikkuWorkflowComplexFunc` lets you write arbitrary inline logic — which the CLI cannot serialize. Those steps are absent from the graph, and a run that was interrupted mid-way has nothing durable to resume from.

That's a real trade, and sometimes the right one. It just isn't a default, so a project has to accept it explicitly rather than acquire it by whichever wrapper someone typed first.

## How to Fix

### Preferred: express it with the step DSL

Most complex workflows are DSL workflows with the logic in the wrong place. Move the work into functions and let `workflow.do` sequence them:


```typescript @snippet checkoutWorkflow
```

Branching, retries and error handling all have DSL equivalents — use the `onError` step option rather than a `try`/`catch`, which the DSL doesn't support.

### If the project accepts the trade

Opt in once, project-wide:

```json title="pikku.config.json"
{
  "tsconfig": "./tsconfig.json",
  "srcDirectories": ["src"],
  "outDir": ".pikku",
  "allow": {
    "complexWorkflows": true
  }
}
```

Understand what you're accepting: these workflows won't appear in the workflow graph, can't be replayed, and can't be migrated across a definition change. That's usually acceptable for short, non-durable orchestration and rarely acceptable for anything involving money or external side effects.

## Workflow Best Practices

- Reach for `pikkuWorkflowFunc` first; treat `pikkuWorkflowComplexFunc` as the escape hatch it is.
- Keep step bodies in ordinary functions — a workflow's job is sequencing, not computation.
- Use the `onError` step option instead of `try`/`catch`; the DSL rejects `try`/`catch` by design.
- Let the orchestrator own retries rather than writing a retry loop inside a step.

## Common Mistakes

The wrong shape is a `pikkuWorkflowComplexFunc` that does inline work, such as inserting the order with Kysely and charging Stripe directly in the body. Nothing in it is serialisable, for no real gain.
