# PKU860: Manifest Missing

## Error Message

```
[PKU860] Version manifest not found at /path/to/project/versions.pikku.json. Run 'pikku versions init' to create one.
```

## What Went Wrong

You ran a versions check (`pikku versions check`, or a CI step that calls it), but the project has no `versions.pikku.json` manifest yet.

The manifest is the recorded history of your function contracts: for every versioned function it stores the input/output schema hashes of each published version. The check compares your current code against it — with no manifest, there is nothing to compare against, so the command fails rather than silently passing.

## How to Fix

Initialize the manifest once, then commit it:

```bash
npx pikku versions init
git add versions.pikku.json
git commit -m "chore: initialize pikku version manifest"
```

From then on:

- `pikku versions check` — verifies current contracts against the manifest (run this in CI).
- `pikku versions update` — records intentional contract changes into the manifest after you bump versions.

## Contract Versioning Best Practices

- Commit `versions.pikku.json` — it's a shared record, not a build artifact.
- Run `versions check` in CI so contract breaks are caught in review, not by consumers.
- Initialize the manifest early; adopting it after clients depend on your contracts means the first snapshot can't protect what already shipped.

## Common Mistakes

- Adding `versions.pikku.json` to `.gitignore` — every CI run then fails with PKU860.
- Running the check from a subdirectory whose `rootDir` doesn't contain the manifest.
