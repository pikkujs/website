# PKU482: Format on Non-String Column

## Error Message

```
[PKU482] Column "public.users.age": format 'email' ignored — its resolved type is number, not string. Remove the conflicting kind/tsType.
```

## What Went Wrong

A `format` annotation (like `'email'`, `'uuid'`, or `'url'`) refines the **string** validation schema for a column — it narrows what a string is allowed to contain. It only makes sense when the column's resolved TypeScript type is a plain `string`. Here, `age` resolves to `number`, so an `email` format has nothing to refine and would contradict the actual type. Pikku ignores the format and warns you rather than emitting a schema that can never match.

This is a **warning**, not a blocker (it only fails the build under `--fail-on-warn`). It usually means two annotations are fighting: a `format` that expects a string, and a `kind`/`tsType` (or the real DB type) that resolves to something non-string. One of them is wrong.

## How to Fix

Decide what the column actually is. If it's a number, drop the `format`. If it should be a validated string, remove the conflicting `kind`/`tsType` so it resolves to `string` and the `format` can apply. Both edits happen in `db/annotations.ts` — the hand-editable annotations file.

```typescript title="db/annotations.ts"
// ❌ Wrong — format 'email' on a column that resolves to number; format is ignored
export const annotations = {
  'public.users': {
    age: { kind: 'number', format: 'email' },
  },
}
```

```typescript title="db/annotations.ts"
// ✅ Correct — number column, no string-only format
export const annotations = {
  'public.users': {
    age: { kind: 'number' },
  },
}
```

If the column really is a formatted string, remove the conflicting `kind`/`tsType` so it resolves to `string`:

```typescript title="db/annotations.ts"
// ✅ Correct — resolves to string, so 'email' actually refines it
export const annotations = {
  'public.users': {
    email: { format: 'email' },
  },
}
```

Then regenerate the types:

```bash
pikku db migrate
```

## Database Schema Best Practices

- Apply `format` only to string columns — it validates string contents, not numeric, boolean, or JSON values.
- Don't stack a `format` on top of a `kind`/`tsType` that changes the base type away from `string`; pick one intent per column.
- Let a column's resolved type drive its validation: match the `format` to the type, not the other way around.

## Common Mistakes

Editing the generated schema or the generated classification file to "fix" the type instead of correcting the annotation. `db/schema.d.ts` and `db/classification.gen.ts` are both regenerated on every `pikku db migrate` and any hand-edit is lost.

```typescript title="db/annotations.ts"
// ❌ Wrong — keeping both; the format silently does nothing
export const annotations = {
  'public.users': {
    age: { kind: 'number', format: 'email' },
  },
}
```

```typescript title="db/annotations.ts"
// ✅ Correct — remove whichever annotation doesn't belong
export const annotations = {
  'public.users': {
    age: { kind: 'number' },
  },
}
```
