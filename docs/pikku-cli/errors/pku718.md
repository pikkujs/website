# PKU718: CLI / Core Version Skew

## Error Message

```
[PKU718] @pikku/cli@0.12.36 requires @pikku/core@^0.12.0 (peerDependencies), but 0.11.4 is installed.
Some package managers (bun, yarn) install past an unsatisfied peer range instead of
failing, and a cli/core version skew breaks codegen and runtime with cryptic
missing-export errors.

Fix: @pikku/cli and @pikku/core move together — bump both to the same release (update
any overrides/resolutions pins too), then reinstall. Set PIKKU_ALLOW_CORE_SKEW=1 to
downgrade this to a warning if you have verified the installed pair is compatible.
```

## What Went Wrong

Exactly one `@pikku/core` is installed — so this isn't the duplicate-copy problem — but its version falls outside the peer range the installed `@pikku/cli` declares.

`@pikku/cli` generates code *against* `@pikku/core`: the types it emits, the helpers it references, and the state APIs it wires all come from core. When the two drift, the CLI emits code for a core that isn't there. The failures that follow are unhelpfully far from the cause — missing exports from `#pikku/*.gen.js`, type errors inside generated files you didn't write, or a runtime that can't find a registry method.

The check exists because npm's peer-range enforcement isn't universal: bun and yarn install past an unsatisfied peer range rather than failing, so nothing else stops the skew.

## How to Fix

Bump `@pikku/cli` and `@pikku/core` to the same release and reinstall:

```bash
yarn add @pikku/core@0.12.36
yarn add -D @pikku/cli@0.12.36
yarn install
```

Then regenerate:

```bash
npx pikku prebuild
```

If a pin is holding one of them back, update it too:

```json title="package.json (yarn)"
{
  "resolutions": {
    "@pikku/core": "0.12.36"
  }
}
```

```json title="package.json (npm)"
{
  "overrides": {
    "@pikku/core": "0.12.36"
  }
}
```

Verify what actually landed rather than what you asked for:

```bash
yarn why @pikku/core
npx pikku --version
```

If you've verified the installed pair is compatible — for instance while testing a pre-release — `PIKKU_ALLOW_CORE_SKEW=1` downgrades the failure to a warning.

## Dependency Best Practices

- Treat `@pikku/cli` and `@pikku/core` as one unit: bump them in the same commit, always.
- Pin both, not one — a pin on core alone is the most common way to acquire skew.
- In a monorepo, keep the `@pikku/*` versions in one shared place so workspaces can't drift apart.
- Check `npx pikku --version` against your installed core before debugging a strange codegen error.

## Common Mistakes

```json title="wrong.json"
// ❌ Wrong — core pinned, CLI floating; the next CLI release skews
{
  "dependencies": { "@pikku/core": "0.11.4" },
  "devDependencies": { "@pikku/cli": "^0.12.0" }
}
```

```json title="correct.json"
// ✅ Correct — both on the same release
{
  "dependencies": { "@pikku/core": "0.12.36" },
  "devDependencies": { "@pikku/cli": "0.12.36" }
}
```
