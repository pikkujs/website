# PKU717: Duplicate @pikku/core Version

## Error Message

```
[PKU717] Multiple @pikku/core versions installed: 0.8.2, 0.9.0.
A split @pikku/core means two separate pikkuState registries at runtime — wirings
(workflows, RPCs, queue workers, middleware) register into one copy while the runner
reads another, so they silently fail to resolve (e.g. WorkflowNotFoundError, missing
RPCs). Every @pikku/* package must resolve to a single @pikku/core.

Found:
  0.8.2  node_modules/@pikku/queue-bullmq/node_modules/@pikku/core
  0.9.0  node_modules/@pikku/core

Fix: align all @pikku/* dependencies to the same release (bump them together), or pin
@pikku/core via your package manager's overrides/resolutions, then reinstall so a
single copy is deduped. Set PIKKU_ALLOW_DUPLICATE_CORE=1 to downgrade this to a warning.
```

## What Went Wrong

Your `node_modules` contains **two different versions** of `@pikku/core`. That's not a cosmetic problem: each copy is a separate module instance with its own `pikkuState` registry. Your wiring files register workflows, RPCs, queue workers, and middleware into whichever copy *they* import, while the runtime may read the *other* copy — so things that are plainly registered "don't exist" at runtime. The classic symptom is `WorkflowNotFoundError` for a workflow you can see in your code.

This happens when `@pikku/*` packages are on mismatched releases (e.g. you bumped `@pikku/core` but not `@pikku/queue-bullmq`), so the package manager can't dedupe them to one physical copy.

## How to Fix

1. **Align all `@pikku/*` dependencies to the same release** — bump them together in `package.json`, then reinstall:

```bash
npm install @pikku/core@latest @pikku/queue-bullmq@latest # ...every @pikku/* you use
```

2. **Or pin the version** with your package manager's override mechanism:

```json title="package.json (npm)"
{
  "overrides": { "@pikku/core": "0.9.0" }
}
```

```json title="package.json (pnpm)"
{
  "pnpm": { "overrides": { "@pikku/core": "0.9.0" } }
}
```

Then reinstall and verify only one copy remains:

```bash
npm ls @pikku/core
```

If you knowingly need to run split (rarely a good idea), `PIKKU_ALLOW_DUPLICATE_CORE=1` downgrades the failure to a warning.

## Dependency Best Practices

- Bump the whole `@pikku/*` family in one commit — the packages are released in lockstep.
- After changing Pikku versions, run `npm ls @pikku/core` (or the pnpm/yarn/bun equivalent) before debugging anything else.
- In monorepos, keep `@pikku/*` versions in a single shared place (catalog/syncpack) so workspaces can't drift.
