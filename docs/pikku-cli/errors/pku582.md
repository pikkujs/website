# PKU582: Auth Not Exported

## Error Message

```
[PKU582] pikkuBetterAuth(...) must be assigned to an exported const, e.g. `export const auth = pikkuBetterAuth((services) => betterAuth({...}))` in src/auth/auth.ts
```

Or, when the binding exists but isn't an exported `const`:

```
[PKU582] pikkuBetterAuth(...) must be assigned to an exported const so the CLI can import it. Use `export const auth = pikkuBetterAuth(...)` in src/auth/auth.ts
```

## What Went Wrong

The CLI found a `pikkuBetterAuth(...)` call, but it isn't assigned to an **exported const**. Pikku's codegen imports your auth definition by name to generate the session middleware and auth routes — a bare call, a `let`/`var` binding, or an unexported variable gives it nothing stable to import, so the build fails.

## How to Fix

Assign the call to an exported const:

```typescript title="src/auth/auth.ts"
// ❌ Wrong — bare call, nothing to import
pikkuBetterAuth((services) => betterAuth({ database: services.kysely }))

// ❌ Wrong — not exported
const auth = pikkuBetterAuth((services) => betterAuth({ database: services.kysely }))

// ❌ Wrong — let binding
export let auth = pikkuBetterAuth((services) => betterAuth({ database: services.kysely }))
```

```typescript title="src/auth/auth.ts"
// ✅ Correct — exported const
export const auth = pikkuBetterAuth((services) =>
  betterAuth({
    database: services.kysely,
    emailAndPassword: { enabled: true },
  })
)
```

Note the argument shape: `pikkuBetterAuth` takes a **factory** `(services) => betterAuth({...})`, so your Better Auth config can use Pikku services (database, secrets) at startup.

## Auth Best Practices

- Export the instance under a simple name (`auth`) from a dedicated file.
- Don't re-export it through barrels with renames — keep the binding where it's defined.
- Pass a factory, not a pre-built `betterAuth()` value, so services are injected by Pikku.
