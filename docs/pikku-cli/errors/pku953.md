# PKU953: Secret Revealed Into Sink

## Error Message

```
[PKU953] Function 'provisionWebhook' passes a revealed secret to 'logger.info' at line 42 (path 'credential.token').
  A vault secret must not be written to a log, an audit, a queue, an email or a webhook. Pass the value only to the client that needs it, and reveal it there.
```

This is an **error**-severity diagnostic. It fails the build with `--fail-on-error`, and it only runs when the classification scan is requested — `pikku all --security`.

## What Went Wrong

A function calls `.reveal()` on a vault secret and then passes the revealed value to a **sink**: a logger, an audit record, a queue payload, an email body, or an outbound webhook.

Each of those is a copy of the secret outside the vault, and every one of them persists somewhere the vault's access controls don't reach — a log aggregator, an audit table, a queue's dead-letter store, someone's inbox, a third party's request log. Rotation doesn't clean those up. Neither does deleting the secret. This is the single most common way credentials leak from an otherwise well-configured system, and it's usually accidental: a debug log added during an incident, or a whole object logged for context without noticing what's inside it.

The scan walks the sinks as well as the return type, because a secret written out mid-body never shows up in what the function returns.

## How to Fix

Pass the secret only to the client that needs it, and keep it out of everything else:

```typescript title="src/functions/webhooks.functions.ts"
export const provisionWebhook = pikkuFunc({
  func: async ({ logger, stripe, secrets }, data) => {
    const token = (await secrets.getSecret('WEBHOOK_TOKEN')).reveal()

    const hook = await stripe.webhookEndpoints.create({
      url: data.url,
      secret: token, // ✅ the one place it may go
    })

    logger.info(`provisioned webhook ${hook.id}`) // ✅ identifiers, not credentials
    return { id: hook.id }
  },
})
```

Better still, don't reveal it in the function at all — construct the client with the secret in `services.ts` and let the function use a capability rather than a credential (see [PKU950](./pku950.md)).

### If you're logging an object that contains a secret

Log the fields you need, not the object:

```typescript
// ❌ logger.info('created', credential)
logger.info(`created credential ${credential.id} for ${credential.provider}`)
```

### If the value must cross a boundary

Send a reference — a credential id, a secret id — and let the receiving side resolve it from its own vault. That keeps exactly one copy of the value, in exactly one place.

## Secret Handling Best Practices

- Reveal as late as possible, use immediately, and never assign the revealed value to anything longer-lived than the call.
- Never log, audit or enqueue a whole object that carries a credential — log its identifier.
- Pass secret *references* across process and service boundaries, never secret values.
- Run `pikku all --security` in CI; the scan is off by default because it's expensive, so nothing else will catch this.

## Common Mistakes

```typescript title="wrong.ts"
// ❌ Wrong — the token lands in the log aggregator, forever
const token = (await secrets.getSecret('WEBHOOK_TOKEN')).reveal()
logger.info('provisioning webhook', { url: data.url, token })
```

```typescript title="correct.ts"
// ✅ Correct — the token goes to the client and nowhere else
const token = (await secrets.getSecret('WEBHOOK_TOKEN')).reveal()
await stripe.webhookEndpoints.create({ url: data.url, secret: token })
logger.info(`provisioning webhook for ${data.url}`)
```
