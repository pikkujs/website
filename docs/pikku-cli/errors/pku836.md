# PKU836: Permission Tag Invalid

## Error Message

```
[PKU836] Tag for tag-based permission wiring must be a non-empty string literal.
```

## What Went Wrong

You're wiring permissions by tag, but the tag you passed isn't a usable value. Tag-based permission wiring attaches a set of `pikkuPermission` checks to every function or route that carries a matching tag — so the CLI needs a concrete, non-empty string literal at build time to know which functions the permissions apply to.

This usually happens when the tag is an empty string (`''`), a variable or expression the CLI can't resolve statically, or was left off entirely. Because tags are matched during code generation, a value that only exists at runtime can't be used here.

## How to Fix

Pass a non-empty string literal that matches a tag on your functions or routes:

```typescript title="permissions.ts"
import { pikkuPermission } from '#pikku'
import { addHTTPPermission } from '@pikku/core/http'

export const isAdmin = pikkuPermission(async (ctx) => {
  if (ctx.session?.role !== 'admin') {
    throw new Error('Admin access required')
  }
})

// ✅ Correct: a non-empty string-literal tag
export const adminPermissions = () =>
  addHTTPPermission('admin', [isAdmin])
```

Make sure the tag exists on the functions or routes you want to protect:

```typescript title="routes.ts"
wireHTTP({
  method: 'delete',
  route: '/api/users/:id',
  func: deleteUser,
  tags: ['admin'], // Matched by the 'admin' permission wiring above
})
```

## Permission Best Practices

- Use a literal string for the tag — never a variable, template literal, or computed expression the CLI can't resolve at build time.
- Keep tag names consistent between your permission wiring and the `tags` on your functions/routes; a typo means the permissions silently never apply.
- Prefer a small, well-known set of tags (e.g. `'admin'`, `'internal'`) over ad-hoc strings so authorization stays auditable.

## Common Mistakes

```typescript title="wrong.ts"
// ❌ Wrong — empty tag causes PKU836
export const adminPermissions = () =>
  addHTTPPermission('', [isAdmin])

// ❌ Wrong — non-literal tag can't be resolved at build time
const tag = getTag()
export const adminPermissions = () =>
  addHTTPPermission(tag, [isAdmin])
```

```typescript title="correct.ts"
// ✅ Correct — non-empty string literal
export const adminPermissions = () =>
  addHTTPPermission('admin', [isAdmin])
```
