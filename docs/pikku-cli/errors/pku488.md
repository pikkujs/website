# PKU488: Schema Load Error

## Error Message

```
[PKU488] Failed to load generated schema '[schemaName]' from the output directory.
```

## What Went Wrong

The CLI tried to load a generated JSON schema from your `.pikku/` output directory, but the file was missing or couldn't be read. Unlike [PKU431](./pku431.md) and [PKU456](./pku456.md), which happen while *generating* a schema, this error happens while *loading* one that should already exist.

The most common cause is a stale or incomplete build: the schema was never generated, or the output directory was cleared, gitignored, or not restored before this step ran. In CI this often shows up when the `.pikku/` directory is excluded from the checkout or cache and the build runs before codegen.

## How to Fix

Regenerate the schemas by running codegen, then re-run your command:

```bash
# ❌ Wrong — building against a stale/missing .pikku output
yarn build
```

```bash
# ✅ Correct — regenerate types and schemas first
npx pikku prebuild
yarn build
```

Make sure the output directory in `pikku.config.json` is where you expect and isn't being wiped between generation and use:

```json title="pikku.config.json"
{
  "srcDirectories": ["src"],
  "outDir": ".pikku"
}
```

### In CI

The generated `.pikku/` output must exist before any step that loads schemas. Either commit it or regenerate it as part of the pipeline:

```yaml
# ✅ Correct — generate before build so schemas are present
- run: npx pikku prebuild
- run: yarn build
```

If `.pikku/` is gitignored (a common setup), confirm your CI actually runs `pikku prebuild` — don't rely on a cached or checked-out copy that may be absent.

## Schema Output Best Practices

- Run `pikku prebuild` after changing function input/output types so schemas stay in sync.
- Treat `.pikku/` as generated: either regenerate it in every environment or commit it consistently — don't do half of each.
- In CI, generate schemas before any build or test step that reads them, not after.

## Common Mistakes

- Running the build in a fresh checkout without running `pikku prebuild` first
- Gitignoring `.pikku/` but not regenerating it in CI
- Deleting or clearing `outDir` mid-build, then running a step that loads schemas
- Pointing `outDir` at a different path than the one used to generate the schemas
