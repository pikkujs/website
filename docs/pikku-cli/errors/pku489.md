# PKU489: Inline Schema

## Error Message

```
[PKU489] Inline schemas are not supported for 'input' in 'createTodo'.
  Extract to an exported variable:
    export const CreateTodoInput = z.object({ text: z.string() })
  Then use: input: CreateTodoInput
```

A second variant fires when the schema's library can't be identified:

```
[PKU489] Function 'createTodo' input schema vendor could not be determined from 'src/functions/todos.functions.ts'. Supported vendors: zod, valibot, arktype, @effect/schema. Ensure your schema is imported from a supported validation library.
```

## What Went Wrong

Runtime schemas (Zod, Valibot, ArkType, Effect Schema) attached to a function's `input`/`output` must be **named, exported variables** — not expressions written inline in the function definition. The CLI extracts schemas by importing the file and reading the exported binding; an inline `z.object({...})` has no name to import, so it can't be turned into JSON Schema, generated types, or Console documentation.

The vendor variant means Pikku found your schema variable but couldn't trace its type back to a supported validation library — usually because it's wrapped in a helper, re-exported through an untyped barrel, or built with an unsupported library.

## How to Fix

### If the schema is inline

```typescript title="todos.functions.ts"
// ❌ Wrong — inline expression, causes PKU489
export const createTodo = pikkuFunc({
  func: async ({ database }, data) => { ... },
  input: z.object({ text: z.string() }),
})
```

```typescript title="todos.functions.ts"
// ✅ Correct — exported variable
export const CreateTodoInput = z.object({ text: z.string() })

export const createTodo = pikkuFunc({
  func: async ({ database }, data) => { ... },
  input: CreateTodoInput,
})
```

### If the vendor can't be determined

Make sure the variable is a plain schema from a supported library, imported directly:

```typescript
// ❌ Wrong — wrapped in a custom helper the checker can't see through
export const CreateTodoInput = mySchemaHelper({ text: 'string' })

// ✅ Correct — direct zod/valibot/arktype/@effect/schema value
import { z } from 'zod'
export const CreateTodoInput = z.object({ text: z.string() })
```

## Schema Best Practices

- Keep schemas in their own file (e.g. `todos.schemas.ts`) — see [PKU490](./pku490.md) for why schemas and wiring calls must not share a file.
- Export every schema; unexported schemas can't be extracted.
- One schema per concept, referenced by both function and tests, so generated types stay the single source of truth.
