# PKU715: Middleware Tag Invalid

## Error Message

```
[PKU715] Tag for middleware wiring must be a non-empty string literal.
```

## What Went Wrong

You're attaching middleware by tag, but the tag Pikku received was empty or wasn't a plain string literal it could read at build time. Tag-based wiring works by matching a static string against the tags applied to your functions and routes — so the inspector has to see the exact tag value in the source. A blank string, or a value computed at runtime (a variable, a template literal with interpolation, a function call), gives it nothing concrete to match against, so the wiring is dropped.

This usually shows up when a tag was left as an empty string during scaffolding, or when someone tried to build the tag dynamically instead of writing it out.

## How to Fix

Pass a non-empty string literal that matches a tag applied to your functions or routes:

```typescript title="wrong.ts"
// ❌ Wrong — empty tag, nothing to match
export const adminMiddleware = () => addHTTPMiddleware('', [requireAdmin])

// ❌ Wrong — computed at runtime, inspector can't read it
const tag = getAdminTag()
export const adminMiddleware = () => addHTTPMiddleware(tag, [requireAdmin])
```

```typescript title="correct.ts"
// ✅ Correct — a literal tag that matches routes tagged 'admin'
export const adminMiddleware = () => addHTTPMiddleware('admin', [requireAdmin])
```

Make sure the same tag is applied to the routes you want the middleware to cover:

```typescript title="admin.http.ts"
wireHTTP({
  method: 'post',
  route: '/api/admin/users',
  func: createUser,
  tags: ['admin'], // matched by the 'admin' middleware group
})
```

## Middleware Best Practices

- Use string literals for tags — Pikku resolves tag wiring statically, so the value must be visible in the source.
- Keep tag names consistent between where they're applied (`tags: ['admin']`) and where they're matched, so the two sides line up.
- Wrap tag-based `addHTTPMiddleware` calls in a factory function (`export const x = () => ...`) to keep them tree-shakeable.

## Common Mistakes

```typescript title="wrong.ts"
// ❌ Wrong — template literal with interpolation isn't a plain literal
export const roleMiddleware = () =>
  addHTTPMiddleware(`role-${role}`, [checkRole])
```

```typescript title="correct.ts"
// ✅ Correct — spell each tag out as its own literal wiring
export const adminMiddleware = () => addHTTPMiddleware('role-admin', [checkRole])
export const editorMiddleware = () => addHTTPMiddleware('role-editor', [checkRole])
```
