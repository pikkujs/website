# PKU581: Duplicate Auth Definition

## Error Message

```
[PKU581] Only one pikkuBetterAuth(...) is allowed per codebase. Found a second in src/auth/admin-auth.ts (first: src/auth/auth.ts).
```

## What Went Wrong

The inspector found two (or more) `pikkuBetterAuth(...)` definitions in your project. Pikku generates its auth wiring — session middleware, auth HTTP routes, generated `auth/` files — from a single Better Auth instance. A second instance would mean two competing sources of sessions and two sets of generated routes, so the build stops at the first duplicate.

This often happens after copying an example into a new file while the old definition still exists, or when a merge resurrects a deleted auth file.

## How to Fix

Keep exactly one `pikkuBetterAuth` and delete the rest:

```typescript title="src/auth/auth.ts"
// ✅ The single auth definition for the whole app
export const auth = pikkuBetterAuth((services) =>
  betterAuth({
    database: services.kysely,
    emailAndPassword: { enabled: true },
  })
)
```

If you need different behaviour for different user types (e.g. admins), configure it *inside* the one instance — Better Auth plugins, multiple providers, and role fields all live in the single `betterAuth({...})` config rather than in separate instances.

## Auth Best Practices

- One `pikkuBetterAuth` per codebase, in a predictable location (e.g. `src/auth/auth.ts`).
- Model user categories with roles/plugins inside the single instance, not with parallel auth stacks.
- After merges, grep for `pikkuBetterAuth` if auth behaves oddly — the error message names both files for you.

## Common Mistakes

```typescript title="wrong.ts"
// ❌ Wrong — a second instance for "admin auth"
export const adminAuth = pikkuBetterAuth((services) => betterAuth({ ... }))
```

```typescript title="correct.ts"
// ✅ Correct — one instance, roles handled via plugins/config
export const auth = pikkuBetterAuth((services) =>
  betterAuth({
    database: services.kysely,
    plugins: [admin()],
  })
)
```
