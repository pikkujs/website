# PKU575: Tag Resolves to No Middleware

## Error Message

```
[PKU575] wireAddon('crm') declares tag 'internal-only', but no addTagMiddleware('internal-only', …) registers anything for it. The tag resolves to an empty middleware list, so it applies no gate to the addon at all. Register middleware for it, or drop the tag if it is only meant to group and document.
```

This is a **warning**. It prints on every build, but only fails the build with `--fail-on-warn`.

## What Went Wrong

A `wireAddon` declaration carries a tag, and no `addTagMiddleware` registers middleware under that tag name.

Tags do two different jobs in Pikku: they group and document, and they attach middleware. Because they look identical in the wiring, a tag that was *meant* to attach a gate but was never registered is indistinguishable from a tag that's purely descriptive — it silently resolves to an empty middleware list and the addon runs ungated. That's the failure this warning exists to catch: security wiring that reads as present and behaves as absent.

The usual cause is a typo between the two call sites, or middleware registered in a file outside the scanned `srcDirectories`.

## How to Fix

### If the tag is meant to gate

Register middleware for it:


```typescript @snippet tagMiddleware
```

Then give the addon the identical string in the `tags` option of `wireAddon`, for example `tags: ['internal-only']`.

The two strings must match exactly — they are the only link between the tag and the gate.

### If the tag is only for grouping


Just leave `tags` off the `wireAddon` call, for example `wireAddon({ name: 'crm', package: '@acme/addon-crm' })`.

If you use tags for documentation across the project, prefer a naming convention that makes intent obvious (`docs:billing` vs `gate:internal-only`) so a reader can tell which tags are load-bearing.

## Middleware Best Practices

- Register the middleware before adding the tag to a wiring, so a tag never exists in a half-wired state.
- Keep `addTagMiddleware` calls in one wirings file — that file is then the complete list of gating tags.
- Don't reuse a documentation tag as a gate later; add a separate one so the grouping doesn't quietly change behaviour.
- Run builds with `--fail-on-warn` in CI if your project treats gates as non-negotiable.

## Common Mistakes

A mismatch such as `addTagMiddleware('internalOnly', ...)` against `tags: ['internal-only']` leaves the addon ungated, because the names don't match.
