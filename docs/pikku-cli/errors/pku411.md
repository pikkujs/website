# PKU411: Wires Not Destructured

## Error Message

```
[PKU411] Function 'createTodo' does not destructure its wires parameter, preventing tree-shaking optimization.
```

## What Went Wrong

This is a **warning-level lint**, not a build blocker (it only fails the build with `--fail-on-warn`). Your function, middleware, or permission accepts the wires parameter (the object carrying interaction handles like `rpc`, `channel`, `http`, `workflow`) without destructuring it.

Just like with services ([PKU410](./pku410.md)), the inspector reads the destructuring pattern to learn which wires the function actually touches. An opaque `wires` parameter means Pikku must assume all of them are used, so none of the wire plumbing can be tree-shaken from deployments where it's unnecessary.

## How to Fix

Destructure the wires you use in the parameter list:

```typescript title="orders.functions.ts"
// ❌ Warns — every wire is assumed used
export const processOrder = pikkuFunc<Order, Receipt>(
  async ({ database }, data, wires) => {
    await wires.rpc.invoke('sendReceipt', data)
    return database.get('receipts', data.id)
  }
)
```

```typescript title="orders.functions.ts"
// ✅ Correct — only 'rpc' is bundled for this function
export const processOrder = pikkuFunc<Order, Receipt>(
  async ({ database }, data, { rpc }) => {
    await rpc.invoke('sendReceipt', data)
    return database.get('receipts', data.id)
  }
)
```

## Tree-Shaking Best Practices

- Destructure in the signature — pulling wires out inside the body keeps them invisible to the inspector.
- Omit the wires parameter entirely when the function doesn't use it.
- Keep helpers wire-free; do wire calls at the function level where the inspector can see them.

## Common Mistakes

```typescript title="wrong.ts"
// ❌ Still warns — the parameter itself is opaque
async ({ database }, data, wires) => {
  const { rpc } = wires
  ...
}
```

```typescript title="correct.ts"
// ✅ Correct
async ({ database }, data, { rpc }) => { ... }
```
