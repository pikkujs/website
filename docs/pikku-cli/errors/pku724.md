# PKU724: SingletonServices Type Unresolved

## Error Message

```
[PKU724] 'SingletonServices' resolved to no services at all, which means it did not resolve.
Declared in src/application-types.d.ts.

This is usually a stale or partial generated tree: a source file imports a `#pikku/*` leaf that the current output no longer writes, so the type it feeds resolves to an error type. Delete the output directory and re-run to rebuild it from scratch.
```

## What Went Wrong

Your `SingletonServices` type was found and read, and it came back with **zero** properties.

That is never a real answer. `SingletonServices` extends `CoreSingletonServices`, which always carries the framework's own singletons — `logger`, `variables`, `schema` and friends — so even an application that adds nothing of its own has services. An empty result means TypeScript could not resolve the type at all and handed the inspector an error type instead.

Pikku fails here rather than continuing, because continuing is worse. With no services to write down, every entry in the generated `RequiredSingletonServices` becomes optional, and the real failure resurfaces later as dozens of "possibly undefined" errors in files you never touched. This error stops at the cause.

The usual reason is a **stale or partial generated tree**. A source file imports a `#pikku/*` leaf that the current output no longer writes — because a wiring was renamed or removed, or a previous run failed part-way — and that broken import poisons the type chain feeding `SingletonServices`.

## How to Fix

### Rebuild the generated tree from scratch

This clears the common case. Delete your output directory (the `outDir` from `pikku.config.json`, `.pikku` by default) and regenerate:

```bash
rm -rf .pikku
pikku all
```

### If it survives a clean rebuild, find the broken import

A single unresolved `#pikku/*` import is enough. Type-check the project and look for the first module-resolution error, not the "possibly undefined" noise that follows it:

```bash
pikku all --tsc
```

Then fix the import that no longer has a leaf behind it:

```typescript title="src/services.ts"
// ❌ Wrong — this leaf is no longer generated, so every type downstream breaks
import type { SingletonServices } from '#pikku/rpc-legacy.gen.js'
```

```typescript title="src/services.ts"
// ✅ Correct — import a door the current output actually writes
import type { SingletonServices } from '#pikku/function'
```

### Check the declaration is reachable

The inspector only sees interfaces it can walk to. Make sure yours is exported, extends `CoreSingletonServices`, and lives under a path listed in `srcDirectories`:

```typescript title="src/application-types.d.ts"
// ✅ Correct
export interface Config extends CoreConfig {}

export interface SingletonServices extends CoreSingletonServices<Config> {
  kysely: KyselyService
}
```

The error message prints the file it read under `Declared in` — if that path is not the file you expected, the inspector picked up a different declaration.

## Service Type Best Practices

- Delete `outDir` whenever you rename or remove a wiring; a half-written tree is the single biggest source of this error.
- Never hand-edit files under `.pikku` — the next run overwrites them, and a stale edit resolves to an error type in the meantime.
- Keep `SingletonServices` in a dedicated types file that imports only what it needs, so one unrelated broken import cannot take it down.
- Run `pikku all --tsc` in CI, so a poisoned type chain fails the build instead of reaching a deploy.

## Common Mistakes

Treating the "possibly undefined" fallout as the bug and adding non-null assertions to silence it. That buries the cause and leaves every service genuinely optional at runtime.

```typescript title="src/functions/get-user.function.ts"
// ❌ Wrong — patching the symptom of an unresolved SingletonServices
export const getUser = pikkuFunc<string, User>({
  func: async ({ kysely }, id) => kysely!.selectFrom('user').run(id),
})
```

```typescript title="src/functions/get-user.function.ts"
// ✅ Correct — fix the type resolution, and the service is required again
export const getUser = pikkuFunc<string, User>({
  func: async ({ kysely }, id) => kysely.selectFrom('user').run(id),
})
```
