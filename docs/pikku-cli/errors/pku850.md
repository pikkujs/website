# PKU850: Duplicate Function Version

## Error Message

```
[PKU850] Duplicate version 2 for function 'getTodo': 'getTodo@v2' and 'getTodoV2'.
```

## What Went Wrong

Two function definitions resolve to the **same version of the same base function**. Pikku's function versioning lets several versions of a function coexist (`getTodo@v1`, `getTodo@v2`, …), resolved from either an explicit `version:` property or a versioned name. Here, two different definitions both claim version 2 — the runtime would have no way to decide which one a `getTodo@v2` call should hit, so the build fails.

This usually comes from mixing the two declaration styles (a `getTodoV2` export *and* a `getTodo` with `version: 2`), or from a copy-paste that kept the old version number.

## How to Fix

Keep exactly one definition per version. Either fix the duplicated number:

```typescript title="todos.functions.ts"
// ❌ Wrong — both claim v2
export const getTodoV2 = pikkuFunc<...>({ ... })
export const getTodo = pikkuFunc<...>({ version: 2, ... })
```

```typescript title="todos.functions.ts"
// ✅ Correct — sequential, unique versions
export const getTodoV2 = pikkuFunc<...>({ ... })
export const getTodo = pikkuFunc<...>({ version: 3, ... })
```

Or delete the stale duplicate if the second definition was meant to replace the first.

## Versioning Best Practices

- Pick one convention per codebase — either `V<n>` name suffixes or explicit `version:` properties — and stick to it.
- Versions must be sequential; see [PKU864](./pku864.md) for the gap rule.
- Old versions are immutable once published ([PKU861](./pku861.md)); create a new version instead of editing.

## Common Mistakes

```typescript title="wrong.ts"
// ❌ Wrong — copied v2 to start v3, forgot to bump
export const getTodoV2New = pikkuFunc<...>({ version: 2, ... })
```

```typescript title="correct.ts"
// ✅ Correct
export const getTodo = pikkuFunc<...>({ version: 3, ... })
```
