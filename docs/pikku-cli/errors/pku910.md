# PKU910: PII in Output

## Error Message

```
[PKU910] Function 'getUser' exposes secret-classified field(s) in its return type: 'passwordHash', 'apiToken'.
  Secret fields must never appear in function output. Strip these fields before returning or change the column classification.
```

Or, for private/PII fields returned from an unauthenticated function:

```
[PKU910] Sessionless function 'getPublicProfile' exposes private-classified field(s) in its return type: 'email'.
  Private fields are only safe to return from authenticated (sessioned) functions. Either require a session (use pikkuFunc) or mark the column @public if it is safe to expose publicly.
```

## What Went Wrong

This diagnostic comes from Pikku's **data classification scan** — an opt-in security lint that runs with `pikku all --security`. It walks each function's *actual inferred return type* looking for classification brands (`Secret<T>`, `Private<T>`, `Pii<T>`, typically derived from column classifications on your database schema) and enforces two rules:

- **`secret`** fields must never appear in any function's output — sessioned or not.
- **`private`/`pii`** fields may only be returned by authenticated functions (`pikkuFunc`); a sessionless function returning them would leak personal data to anonymous callers.

The scan is severity `error`: it's printed always, and blocks the build when the CLI runs with `--fail-on-error`.

## How to Fix

### If the field shouldn't be in the output

Strip it before returning, and make the return type say so:

```typescript title="users.functions.ts"
// ❌ Wrong — returns the raw row, passwordHash included
export const getUser = pikkuFunc<{ id: string }, UserRow>(
  async ({ database }, { id }) => database.get('users', id)
)
```

```typescript title="users.functions.ts"
// ✅ Correct — explicit safe projection
export const getUser = pikkuFunc<{ id: string }, PublicUser>(
  async ({ database }, { id }) => {
    const { passwordHash, apiToken, ...safe } = await database.get('users', id)
    return safe
  }
)
```

### If the caller must be authenticated to see it

Change the function to `pikkuFunc` (session required) instead of `pikkuSessionlessFunc`.

### If the field is actually public

Fix the classification at the source (e.g. mark the column `@public` in your schema) rather than fighting the lint per function.

## Data Classification Best Practices

- Classify at the schema/column level once; let the type system propagate it — that's what makes this scan possible.
- Prefer projection types (`PublicUser`) over ad-hoc `omit` calls so the safe shape is reusable and visible.
- Run `pikku all --security` in CI on a schedule or pre-release, since the return-type inference is too expensive for every dev build.
