# PKU343: Addon Exposed Function Not Found

## Error Message

```
[PKU343] wireAddon('shop') lists 'getOrdr' under expose, but @acme/addon-shop publishes no such function.
```

## What Went Wrong

`wireAddon`'s `expose` option got a list of function names, and one of them isn't a function the addon publishes. It's usually a typo, or a function the addon renamed.

The list decides what `rpc.exposed`, and so `POST /rpc/:rpcName`, can reach for this addon instance. A name that matches nothing is an endpoint you think you're serving but aren't. Clients get a 404 and nothing else tells you why.

In a project generated by `pikku all`, the same mistake is also a type error, because the generated `#pikku/addon` types `expose` against each installed addon's function names. This build check covers what the types miss: a wiring written before generation has run, or a project that isn't type-checked in CI.

## How to Fix

List the functions the addon publishes:

```bash
cat node_modules/@acme/addon-shop/.pikku/function/pikku-functions-meta.gen.json | jq 'keys'
```

Then fix the list:

```typescript title="wirings/addons.wirings.ts"
// ❌ Wrong: 'getOrdr' isn't a function the addon publishes
wireAddon({ name: 'shop', package: '@acme/addon-shop', expose: ['getOrdr'] })
```

```typescript title="wirings/addons.wirings.ts"
// ✅ Correct
wireAddon({ name: 'shop', package: '@acme/addon-shop', expose: ['getOrder'] })
```

If you don't need your own list, leave `expose` unset (or set it to `true`) to use the addon's `expose: true` declarations, or set it to `false` to expose nothing.

## Best Practices

- Name the functions you mean. What `rpc.exposed` can reach is your public API, and the shorter it is, the less there is to misuse.
- The list can name functions the addon never marked `expose: true`. Check that each one is gated, by its own `auth` or by the instance's `auth`/`scopes`, before you expose it.
