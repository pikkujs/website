# PKU338: Remote Addon Not a Dev Dependency

## Error Message

When the package is in `dependencies`:

```
[PKU338] Remote addon 'crm' ('@acme/addon-crm') is a production dependency, but wireRemoteAddon consumes it for types only — its handlers run on the host. Move '@acme/addon-crm' from "dependencies" to "devDependencies".
```

When the package is missing entirely:

```
[PKU338] Remote addon 'crm' ('@acme/addon-crm') is wired with wireRemoteAddon but is not in "devDependencies". Add '@acme/addon-crm' to "devDependencies" (types only).
```

## What Went Wrong

`wireRemoteAddon` declares an addon whose functions run **somewhere else** — on the host that owns them — and are reached over RPC. Your project never executes the addon's code; it only needs the addon's *types* so calls are checked at compile time and the generated client is typed.

That makes the package a build-time dependency, which is what `devDependencies` means. Listing it under `dependencies` ships the whole addon — and its transitive runtime dependencies, its credentials wiring, its native modules — into every production bundle, image and Lambda that never calls any of it. The most common symptom is a deployment artifact that is much larger than expected, or a cold start pulling in a database driver the service doesn't use.

The second form of the message means the package isn't declared at all, so types resolve only by accident of hoisting and will break on a clean install.

## How to Fix

Move the package into `devDependencies`:

```json title="package.json"
{
  "dependencies": {
    "@pikku/core": "^0.12.0"
  },
  "devDependencies": {
    "@acme/addon-crm": "^1.4.0"
  }
}
```

Then reinstall and regenerate:

```bash
yarn install
npx pikku prebuild
```

If you actually want the addon's handlers to run **inside** this project, you don't want a remote addon at all — use `wireAddon` and keep the package in `dependencies`:

```typescript title="wirings/addons.wirings.ts"
// Runs locally — package belongs in "dependencies"
wireAddon({ name: 'crm', package: '@acme/addon-crm' })

// Runs on a remote host — package belongs in "devDependencies"
wireRemoteAddon({ name: 'crm', package: '@acme/addon-crm' })
```

## Addon Wiring Best Practices

- Decide *where the handlers run* first; the dependency section follows from that, not the other way round.
- Keep `wireAddon` and `wireRemoteAddon` declarations in one wirings file so the local/remote split is readable at a glance.
- After moving a package between sections, run a clean install — hoisting can hide a missing declaration until CI.
- Never rely on a transitive install for a package you import types from; declare it explicitly.

## Common Mistakes

```json title="wrong.json"
// ❌ Wrong — a remote addon shipped into the production bundle
{
  "dependencies": {
    "@acme/addon-crm": "^1.4.0"
  }
}
```

```json title="correct.json"
// ✅ Correct — types only
{
  "devDependencies": {
    "@acme/addon-crm": "^1.4.0"
  }
}
```
