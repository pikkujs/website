# PKU675: expectEventually Is Scenario-Only

## Error Message

```
[PKU675] Workflow 'processOrder' calls workflow.expectEventually(), which is only available in scenarios (pikkuScenario). Move it into a scenario, or drive the assertion outside the workflow.
```

## What Went Wrong

A regular workflow (defined with `pikkuWorkflow`) calls `workflow.expectEventually()`. That primitive is a **test/eval assertion** — it polls until a condition holds or times out — and it only exists in scenarios. Production workflows must stay free of test semantics: an assertion that "eventually" passes has no meaningful failure mode in a durable workflow (retry? compensate? crash?), so the inspector rejects it at build time.

## How to Fix

### If this code is really a test of your system

Make it a scenario instead of a workflow:

```typescript title="order.scenario.ts"
// ✅ Correct — assertions belong in scenarios
export const orderIsFulfilled = pikkuScenario(
  async ({ logger }, _, { workflow, actors }) => {
    await workflow.do('place order', 'placeOrder', { sku: 'A1' }, { actor: actors.buyer })
    await workflow.expectEventually(
      'order shipped',
      'getOrderStatus',
      { id: 'A1' },
      { actor: actors.buyer, until: (s) => s.status === 'shipped' }
    )
  }
)
```

### If this is a production workflow that must wait on something

Model the wait explicitly — a step that polls with its own retry policy, a trigger, or a queue hand-off — rather than an assertion:

```typescript title="order.workflow.ts"
// ✅ Correct — an explicit step with real failure semantics
export const processOrder = pikkuWorkflow(async (_, order, { workflow }) => {
  await workflow.do('charge card', 'chargeCard', order)
  await workflow.do('await shipment confirmation', 'waitForShipment', {
    orderId: order.id,
  })
})
```

## Workflow Best Practices

- Workflows describe what *must* happen; scenarios describe what you *expect to observe*. Keep the vocabularies separate.
- If you're tempted to assert inside a workflow, you probably want a scenario that drives that workflow via an actor.
- Give long waits their own named step so retries and timeouts are visible in the Console run view.
