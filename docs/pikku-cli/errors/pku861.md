# PKU861: Function Version Modified

## Error Message

```
[PKU861] Contract for getTodo@v2 has changed (recorded: a1b2c3d4/e5f6a7b8, current: 9f8e7d6c). Existing versions are immutable.
```

`pikku versions check` renders it with more context:

```
✗ getTodo@v2 — published contract was modified
  Recorded hash: a1b2c3d4
  Current hash:  9f8e7d6c

  Published versions are immutable. Either revert
  the schema change or create version 3 instead.
```

## What Went Wrong

The input or output schema of an **already-recorded function version** no longer hashes to what `versions.pikku.json` recorded when that version was published. Published versions are immutable by design: clients were generated against `getTodo@v2`'s exact contract, and changing it in place would break them silently. The manifest exists precisely to catch this.

Note this is about the *contract* (input/output shapes), not the implementation — you can fix bugs in the function body freely.

## How to Fix

### If the contract change was unintentional

Revert the schema/type change on the published version. Often it's a shared type that drifted — a field added to an interface that `getTodo@v2` also uses.

### If the contract change is intentional

Don't edit v2 — create v3 alongside it:

```typescript title="todos.functions.ts"
// ✅ Correct — v2 untouched, new contract gets a new version
export const getTodoV2 = pikkuFunc<{ id: string }, Todo>(...)          // unchanged
export const getTodo = pikkuFunc<{ id: string }, TodoWithTags>({
  version: 3,
  func: async ({ database }, { id }) => ...,
})
```

Then record it:

```bash
npx pikku versions update
```

## Contract Versioning Best Practices

- Treat shared input/output types as part of the published contract — changing them changes every version that references them.
- Never hand-edit hashes in `versions.pikku.json` to make the check pass; that defeats its purpose.
- Keep old versions thin: often the old version can delegate to the new function internally while preserving its contract.
