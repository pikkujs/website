# PKU463: Schema Reference Unresolved

## Error Message

```
[PKU463] 1 function contract names a schema that was never generated, so calling it fails at runtime with MissingSchemaError: createOrder.input → 'CreateOrderInput'. The usual cause is a named type used as the function's input/output that is declared but not exported — export it, or inline the type at the call site.
```

## What Went Wrong

A function's contract names a type — as its input or its output — and no schema was generated for that name. At runtime the validator looks the schema up by name, finds nothing, and throws `MissingSchemaError` on the first call.

Almost always the type is declared but not **exported**. Pikku's inspector walks your exported declarations to decide what to generate a schema for; a type that never leaves its module is invisible to that walk, even though TypeScript resolves it perfectly well inside the file. The code compiles, and the failure waits until the first request.

## How to Fix

Export the type:

```typescript @snippet ea-exported-contract-type
```

Or inline the type at the call site, so there is no name to resolve:

```typescript @snippet ea-inline-contract-type
```

Then regenerate:

```bash
pikku all
```

## Best Practices

- Export every type you name in a function contract — treat it as part of the function's public surface, because it is.
- Prefer schema-based functions (`input:` / `output:` with a Zod schema) when you want the contract and the validator to be the same artifact.
- Re-run `pikku all` after moving or renaming a contract type; a stale generated schema resolves to the old name.

## Common Mistakes

Re-exporting the type from a barrel file and assuming that counts. The inspector resolves the declaration where the function is defined, so the type must be exported from the module that declares it.

A local `type CreateOrderInput = ...` followed by `export type { CreateOrderInput }` is still a local declaration. Export it at the declaration: `export type CreateOrderInput = ...`.
