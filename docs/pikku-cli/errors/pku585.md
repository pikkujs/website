# PKU585: Duplicate Personas Definition

## Error Message

When the second call is in a different file:

```
[PKU585] Only one definePersonas(...) is allowed per codebase, so there is one place to read the declarations from and one place to add to. Found a second in src/personas/staff.ts (first: src/personas/customers.ts). Declare them all in one call.
```

When both calls are in the same file:

```
[PKU585] Only one definePersonas(...) is allowed per codebase, so there is one place to read the declarations from and one place to add to. Found a second call in src/personas/index.ts. Declare them all in one call.
```

## What Went Wrong

`definePersonas` was called more than once. It's a single-declaration construct: exactly one call per codebase.

`definePersonas` takes a keyed object, so a single call already declares as many personas as you like. Splitting it across calls buys nothing and costs the thing the construct exists for — one place to read the cast from, and one place to add to. The CLI extracts personas by AST parsing and generates a `PersonaId` union plus a `personas.gen.json` that the console and `pikku persona run` read straight off disk; that only works when there's one authoritative declaration.

A second call in the *same file* is refused too. "The file" isn't an answer to "where do I add a persona?" when the file holds two calls.

Generated files (`*.gen.ts`) are exempt and never claim the slot, so a scaffolded `pikku-personas.gen.ts` won't collide with your own declaration.

## How to Fix

Merge every call into one keyed object:

```typescript title="src/personas.ts"
import { definePersonas } from '@pikku/core/persona'

definePersonas({
  susan: {
    name: 'Susan',
    jobTitle: 'Buys for a small café',
    roles: ['buyer'],
    personality: 'Hunts cheap deals. Tries three coupon codes before giving up.',
    goals: ['Get the weekly order in under five minutes'],
    disposition: 'careless',
    account: {},
  },
  marcus: {
    name: 'Marcus',
    jobTitle: 'Warehouse supervisor',
    roles: ['staff'],
    personality: 'Methodical. Reads every confirmation screen.',
    goals: ['Reconcile the day\'s deliveries'],
    disposition: 'careful',
    account: {},
  },
})
```

If the personas are currently spread across domain files, keep the *definitions* split and merge only at the call site:

```typescript title="src/personas.ts"
import { definePersonas } from '@pikku/core/persona'
import { buyerPersonas } from './personas/buyers.js'
import { staffPersonas } from './personas/staff.js'

definePersonas({ ...buyerPersonas, ...staffPersonas })
```

Note that `definePersonas` is read statically — the spread above works because the CLI can resolve the object literals, but a computed or conditionally-built object cannot be extracted (see [PKU124](./pku124.md)).

## Persona Best Practices

- Keep the single `definePersonas` call in a predictable place — `src/personas.ts` — so newcomers find the cast immediately.
- Declare personas that only get acted upon (the account an admin bans, the colleague a document is shared with) alongside the ones that run; declaring is not running.
- Use plain object literals; personas are parsed, never evaluated.
- Never edit `pikku-personas.gen.ts` — it's regenerated from your declaration.

## Common Mistakes

```typescript title="wrong.ts"
// ❌ Wrong — two calls, two places to look
// src/personas/buyers.ts
definePersonas({ susan: { /* … */ } })

// src/personas/staff.ts
definePersonas({ marcus: { /* … */ } })
```

```typescript title="correct.ts"
// ✅ Correct — one call
// src/personas.ts
definePersonas({
  susan: { /* … */ },
  marcus: { /* … */ },
})
```
