# PKU484: Form on Non-String Column

## Error Message

```
[PKU484] Column "public.users.login_count": form 'hashed' ignored — its resolved type is number, not string. Ciphertext and digests are text; migrate the column or drop the form.
```

## What Went Wrong

A `form` annotation (`'hashed'`, `'wrapped'`, `'sealed'`) says the column holds a transformed value rather than the original — a digest, or ciphertext. Both are text. A column whose resolved type is `number`, `boolean`, or a JSON object has nowhere to put them, so Pikku ignores the `form` and tells you rather than emitting a brand that could never compile.

This is a **warning**, not a blocker (it only fails the build under `--fail-on-warn`). It usually means the annotation was added to the wrong column, or the column's type was never migrated to text.

## How to Fix

Decide which half is wrong: the column type or the `form`.

If the column really holds a digest or ciphertext, migrate it to a text type first — that's a schema decision, so it goes through a SQL migration, not the annotations file:

```sql title="db/migrations/0007-token-to-text.sql"
ALTER TABLE users ALTER COLUMN api_token TYPE text;
```

If the column is genuinely numeric, drop the `form`:

```typescript title="db/annotations.ts"
// ❌ Wrong — a digest cannot live in a number column; the form is ignored
export const annotations = {
  'public.users': {
    loginCount: { classification: 'secret', form: 'hashed' },
  },
}
```

```typescript title="db/annotations.ts"
// ✅ Correct — no form on a numeric column
export const annotations = {
  'public.users': {
    loginCount: { classification: 'private' },
  },
}
```

Then regenerate the types:

```bash
pikku db migrate
```

## Database Schema Best Practices

- Store anything you intend to hash, wrap, or seal in a text column from the start — the transformed value is always text, whatever the original was.
- Change a column's type through a forward migration; migrations are immutable, so never edit one that has already been applied.
- Keep `form` and `classification` on the same column deliberately: the first describes storage, the second exposure.

## Common Mistakes

Adding a `kind` or `tsType` that resolves the column away from `string` while leaving the `form` in place. The two annotations then contradict each other and the `form` silently does nothing.

```typescript title="db/annotations.ts"
// ❌ Wrong — tsType pulls the column off string, so the form is dropped
export const annotations = {
  'public.users': {
    secretBlob: { kind: 'json', tsType: 'Blob', form: 'wrapped' },
  },
}
```

```typescript title="db/annotations.ts"
// ✅ Correct — ciphertext is text, and stays text
export const annotations = {
  'public.users': {
    secretBlob: { classification: 'secret', form: 'wrapped' },
  },
}
```
