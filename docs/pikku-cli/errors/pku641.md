# PKU641: Invalid DSL Workflow

## Error Message

```
[PKU641] Workflow 'myWorkflow' does not conform to DSL workflow rules:
Could not determine input parameter name
```

Or one of several sub-messages depending on what went wrong:

```
[PKU641] Workflow 'myWorkflow' does not conform to DSL workflow rules:
- while and do-while loops are not allowed in DSL workflows
```

```
[PKU641] Workflow 'myWorkflow' uses pikkuWorkflowFunc but contains inline steps
which are not allowed in DSL workflows. Use pikkuWorkflowComplexFunc instead.
```

## What Went Wrong

Pikku's inspector statically analyzes DSL workflows to extract a serializable step graph — this is what makes workflows resumable, observable, and durable. PKU641 fires when your workflow function can't be parsed into that graph.

There are a few ways this happens:

### 1. Missing or destructured input parameter

The DSL extractor needs to track which variables come from the workflow input vs the context. To do that, it needs the input to be a simple named parameter in the second position.

```typescript
// ❌ Only one parameter — missing the input
pikkuWorkflowFunc(async (workflow) => { ... })

// ❌ Destructured input — can't be tracked
pikkuWorkflowFunc(async (workflow, { userId, amount }) => { ... })

// ✅ Simple named parameter
pikkuWorkflowFunc(async (workflow, input) => { ... })
```

### 2. Disallowed control flow

DSL workflows only support a specific set of constructs so the inspector can serialize the execution graph. `while`, `do-while`, `for`, and `for-in` loops are not allowed. Use `for...of` for iteration instead.

```typescript
// ❌ while loops not allowed
while (retries > 0) { ... }

// ❌ do-while not allowed
do { ... } while (condition)

// ❌ for loop not allowed
for (let i = 0; i < items.length; i++) { ... }

// ✅ for-of is fine
for (const item of items) { ... }
```

### 3. Inline workflow.do() in a `pikkuWorkflowFunc`

`pikkuWorkflowFunc` is strict DSL — every step must be an RPC call by name. Inline functions passed directly to `workflow.do()` aren't serializable. If you need inline steps, use `pikkuWorkflowComplexFunc`.

```typescript
// ❌ Inline function in pikkuWorkflowFunc
pikkuWorkflowFunc(async (workflow, input) => {
  await workflow.do('step', async () => { ... }) // Not allowed
})

// ✅ RPC call by name in pikkuWorkflowFunc
pikkuWorkflowFunc(async (workflow, input) => {
  await workflow.do('step', 'myRpc', input.data)
})

// ✅ Inline function is fine in pikkuWorkflowComplexFunc
pikkuWorkflowComplexFunc(async (workflow, input) => {
  await workflow.do('step', async () => { ... }) // Allowed
})
```

### 4. Un-awaited workflow calls

Every `workflow.do()` and `workflow.sleep()` call must be awaited (or collected into a `Promise.all`).

```typescript
// ❌ Not awaited
workflow.do('step', 'myRpc', input.data)

// ✅ Awaited
await workflow.do('step', 'myRpc', input.data)

// ✅ Parallel via Promise.all
await Promise.all([
  workflow.do('step-a', 'rpcA', input.x),
  workflow.do('step-b', 'rpcB', input.y),
])
```

## Which wrapper should I use?

| Wrapper | Inline steps | DSL serialization | Resumable |
|---|---|---|---|
| `pikkuWorkflowFunc` | No | Full | Yes |
| `pikkuWorkflowComplexFunc` | Yes | Best-effort | Yes (if no inline steps) |

If you need inline logic that can't be expressed as RPC calls, switch to `pikkuWorkflowComplexFunc`. If your workflow is all RPC calls, `pikkuWorkflowFunc` gives you the strictest guarantees.
