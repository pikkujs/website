# PKU865: Manifest Integrity Error

## Error Message

```
[PKU865] Manifest integrity error for getTodo: latest field (2) inconsistent with version keys (max: 3).
```

`pikku versions check` renders it as:

```
✗ getTodo — versions.pikku.json integrity error
  "latest" field: 2
  Highest version key: 3

  The manifest is corrupted. Run:
  npx pikku versions-update
```

## What Went Wrong

Inside `versions.pikku.json`, a function's `latest` field doesn't match the highest key in its `versions` map. Each manifest entry stores both — the per-version hash records and a `latest` pointer — and they must agree. When they don't, the manifest was corrupted, almost always by a hand-edit or a botched merge-conflict resolution (one side's `latest` kept with the other side's `versions` map).

## How to Fix

Let the CLI rebuild the entry from your code:

```bash
npx pikku versions update
npx pikku versions check
```

If `update` produces something unexpected, inspect the entry first and restore a sane baseline from git history:

```json title="versions.pikku.json (corrupted)"
{
  "contracts": {
    "getTodo": {
      "latest": 2,
      "versions": { "1": "…", "2": "…", "3": "…" }
    }
  }
}
```

The correct state has `latest` equal to the highest key (here `3`). `pikku versions update` fixes the pointer; use `git log -p versions.pikku.json` if you need to verify which versions were genuinely published.

## Contract Versioning Best Practices

- Don't hand-edit `versions.pikku.json`; drive it through `pikku versions init/update` only.
- Merge conflicts in the manifest deserve a real merge of the JSON, not ours/theirs — see [PKU863](./pku863.md).
- Add `pikku versions check` to CI so corruption is caught at the commit that introduced it.
