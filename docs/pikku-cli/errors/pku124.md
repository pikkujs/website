# PKU124: Invalid Value

## Error Message

```
[PKU124] Secret override 'stripeKey' in addon 'payments' (@acme/payments-addon) does not exist. Available secrets: STRIPE_SECRET_KEY, DATABASE_URL
```

Other variants of the same code:

```
[PKU124] Credential override 'github' in addon 'ci' (@acme/ci-addon) does not exist. Available credentials: githubApp
[PKU124] Variable override 'baseUrl' in addon 'crm' (@acme/crm-addon) does not exist. Available variables: API_BASE_URL
[PKU124] Function 'processOrder' node config has invalid type 'step'. Must be 'trigger', 'action', or 'end'.
```

## What Went Wrong

A property in your Pikku configuration has a value outside the set the inspector accepts. The two common cases:

1. **Addon overrides that point at nothing.** When you wire an addon you can map its secrets, credentials, or variables onto your app's own definitions (`secretOverrides`, `credentialOverrides`, `variableOverrides`). The key you used doesn't match any secret/credential/variable defined in your app, so the override could never take effect.
2. **An enum-like property with a wrong value**, e.g. a function's `node.type`, which must be exactly `'trigger'`, `'action'`, or `'end'`.

Pikku fails the build because both cases would otherwise surface as confusing runtime behaviour (an addon reading an undefined secret, a node that never renders).

## How to Fix

### If it's an addon override

The error lists what actually exists. Point the override at one of those names — the key on the left is the addon's name for it, the value must be one of *your* definitions:

```typescript title="addons.wiring.ts"
// ❌ Wrong — 'stripeKey' is not a secret your app defines
wireAddon('payments', {
  package: '@acme/payments-addon',
  secretOverrides: { apiKey: 'stripeKey' },
})
```

```typescript title="addons.wiring.ts"
// ✅ Correct — maps the addon's 'apiKey' onto your STRIPE_SECRET_KEY
wireAddon('payments', {
  package: '@acme/payments-addon',
  secretOverrides: { apiKey: 'STRIPE_SECRET_KEY' },
})
```

### If it's a node config type

```typescript
// ❌ Wrong
node: { displayName: 'Process Order', category: 'orders', type: 'step' }

// ✅ Correct — one of 'trigger' | 'action' | 'end'
node: { displayName: 'Process Order', category: 'orders', type: 'action' }
```

## Configuration Best Practices

- Run `pikku all` after editing addon overrides — the error message enumerates the valid names, so you never have to guess.
- Define secrets/credentials/variables before wiring addons that override onto them.
- Prefer copying names from the generated types over typing them by hand.
