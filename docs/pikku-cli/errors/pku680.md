# PKU680: Scenario Has No Assertion

## Error Message

```
[PKU680] Scenario 'checkoutFlow' has given/when steps but never asserts. Add a scenario.then(...) naming what the actor should now see — a flow with no 'then' only proves nothing threw, and contributes nothing to witness coverage.
```

## What Went Wrong

A scenario is written as a step ladder — it has `given` and/or `when` phases — but no `then` phase, and it doesn't set `asserts`.

Such a flow proves exactly one thing: nothing threw. It doesn't check that the order was created, that the email went out, or that the buyer sees anything at all. Worse, it's invisible to witness coverage: it contributes 0/0, so it can never lower the number. That makes an assertion-free flow the cheapest possible way to make a suite look better covered than it is, which is why this fails the build rather than warning.

## How to Fix

Add a `then` naming what the actor should now observe:

```typescript title="tests/checkout.feature.ts"
export const checkoutFlow = pikkuScenario<void, { setUp: true }>({
  title: 'A buyer completes checkout',
  tags: ['scenario'],
  func: async (_services, _data, { scenario, actors }) => {
    await scenario.given(
      'has an item in the cart',
      'addToCart',
      { sku: 'A1' },
      { actor: actors.susan }
    )
    await scenario.when(
      'checks out',
      'submitOrder',
      {},
      { actor: actors.susan }
    )
    await scenario.then(
      'sees the order confirmed',
      'seesOrderStatus',
      { status: 'confirmed' },
      { actor: actors.susan }
    )
  },
})
```

The assertion must be something the *actor* can observe — a page they see, a response they get, a record they can read back. That constraint is the point: it keeps scenarios testing the surface real clients use.

### If the witness is an expectation helper

Some flows assert through an inline helper (`workflow.expectEventually(...)`, a recorded service call, an expected refusal) rather than a `then` step. Those are inline and leave no phase behind, so declare it:

```typescript
export const emailFlow = pikkuScenario<void, { setUp: true }>({
  title: 'Signing up sends a welcome email',
  asserts: true, // the witness is the expectEventually below
  tags: ['scenario'],
  func: async (_services, _data, { scenario, workflow, actors }) => {
    await scenario.when('signs up', 'signUp', { email: 'a@b.com' }, { actor: actors.susan })
    await workflow.expectEventually('emailSent', { to: 'a@b.com' })
  },
})
```

Use `asserts: true` honestly — it's the same kind of claim as `permissionsInBody`, verifiable only by a reader.

## Scenario Best Practices

- Write the `then` first if you can; it's the reason the flow exists.
- Phrase assertions as what the actor sees, not as what the database contains.
- Use `workflow.expectEventually()` for asynchronous outcomes rather than sleeping and hoping.
- Assert on data attributes rather than rendered copy — copy goes through i18n.

## Common Mistakes

```typescript title="wrong.ts"
// ❌ Wrong — drives the whole flow, checks nothing
func: async (_services, _data, { scenario, actors }) => {
  await scenario.given('has an item', 'addToCart', { sku: 'A1' }, { actor: actors.susan })
  await scenario.when('checks out', 'submitOrder', {}, { actor: actors.susan })
}
```

```typescript title="correct.ts"
// ✅ Correct — names the observable outcome
func: async (_services, _data, { scenario, actors }) => {
  await scenario.given('has an item', 'addToCart', { sku: 'A1' }, { actor: actors.susan })
  await scenario.when('checks out', 'submitOrder', {}, { actor: actors.susan })
  await scenario.then(
    'sees the order confirmed',
    'seesOrderStatus',
    { status: 'confirmed' },
    { actor: actors.susan }
  )
}
```
