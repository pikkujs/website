# Internationalization

Pikku's frontends treat every visible string as a message. Messages live in
`messages/<locale>.json`, compiled by [Paraglide JS](https://inlang.com/m/gerre34r/library-inlang-paraglideJs)
into typed message functions. An app that will only ever ship English still
writes them this way: the messages are the seam a second language slots into later,
and the deploy pipeline type-checks them, so an i18n mistake blocks the build
rather than the release.

```typescript
// ❌ hardcoded display text
return <span>Create role</span>

// ✅ a message
return <span>{m.scopes_create_role()}</span>
```

Fixed labels live in `messages/en.json` and are rendered through the `m`
namespace. A label containing a variable is a **parameterized message** —
`m.scopes_delete_confirm({ name })` with
`"scopes_delete_confirm": "Delete {name} for everyone — confirm"` — not English
concatenated around `asI18n(...)`.

## Three axes

"The entire UI is German" is a statement about the product, not the codebase:

| Axis | What it covers | What sets it |
| --- | --- | --- |
| **Identifiers** | Function, component, type and file names; tables and columns | Always English |
| **Meta** | `description` / `name` / `title` authored in code, rendered by the console | `metaLocale` in `pikku.config.json` |
| **Product UI** | Every string the app shows a user | `messages/<locale>.json` + `defaultLocale` |

`baseLocale` stays `en` whatever language the product speaks — it names the
message *source* catalogue every other locale is derived from, not the language
the app is in. Set `defaultLocale` instead.

## Adding a language

1. Add `messages/<locale>.json` with the same keys.
2. Point `defaultLocale` at it in `pikku.config.json`.
3. Render through the locale store: `createLocaleStore` from `@pikku/react` is
   the reactive store behind the messages. The app supplies its locale list, its
   storage key and its startup policy, and passes in Paraglide's
   `overwriteGetLocale` from its own compiled runtime — Pikku never imports one
   app's generated output.

## Enum labels

An enum, status, kind or role value is a closed set, so its label is a static map
entry — never a dynamic lookup. Add `enum__<group>__<member>` keys to the
catalog (`__` separates prefix/group/member; a single `_` joins words within a
segment, e.g. `enum__booking_status__form_received`), then read the value
through the generated map.

`@pikku/paraglide` (wired through `@pikku/paraglide/vite` or the CLI) generates
`i18n-enum.gen.ts` from the catalog, typed against your database enums module
when you point it at one:

```ts
// i18n-enum.gen.ts — AUTO-GENERATED, do not edit
import { m } from './messages.js'
import type { BookingStatus } from '#pikku/db/enums.gen'

export const bookingStatus = {
  enquiry: m.enum__booking_status__enquiry,
  reserved: m.enum__booking_status__reserved,
  confirmed: m.enum__booking_status__confirmed,
} satisfies EnumLabel<BookingStatus>
```

```typescript
import { bookingStatus } from './i18n/i18n-enum.gen'

return <span>{bookingStatus[value]()}</span>
```

Each value is an accessor — call it at render time so the label tracks the active
locale. Reconciliation is enforced by types: a missing key or a dropped DB member
is a compile error. For an open server value, gate it:
`value in bookingStatus ? bookingStatus[value]() : asI18n(value)`.

## RTL

Direction is one setting, not per-component work. Set `dir` once at the document
root from the active locale and the browser (and Mantine) mirror everything —
provided every custom style is flow-relative (`margin-inline-start`,
`text-align: start`, Mantine `ms`/`me`) rather than physical (`margin-left`,
`text-align: left`, `ml`/`mr`). Write logical properties from the start even in
an English-only app; that discipline is what makes Arabic, Hebrew, Farsi or Urdu
just another locale file.

## What not to do

- **Do not resolve a message key at runtime.** No `m['enum__' + x]()`, no
  key-string resolver. A computed key cannot be type-checked or tree-shaken, so a
  renamed message degrades to silent runtime text. Map the discriminant to a
  message *function* instead — the map is checked, a string is not.
- **Do not `asI18n()` a hardcoded English string.** `asI18n` exists to pass
  opaque server data — a name, a slug, an id — through the i18n gate. Fixed copy
  uses `m.<key>()`; an enum value goes through its generated label map.
