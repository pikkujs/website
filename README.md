# pikku.dev

The Pikku website: marketing pages, docs, blog, the SDK explorer and the addon / OpenAPI catalogue.

Built with TanStack Start (Vite 8, React 19, Tailwind 4), Fumadocs in headless mode for content, and shipped as a
Docker image. Docs and blog are prerendered at build time; a small Node server (`server/server.mjs`) serves the
prerendered files, the old-URL redirects and `/healthz`, and renders only the catalogue (`/addons`, `/openapis`) on
request. Cloudflare sits in front as the CDN, so the origin mostly sees cache misses.

## Commands

```sh
npm ci --legacy-peer-deps   # install (needs the legacy flag for peer ranges)
npm run dev                 # dev server on http://localhost:3005
npm run build               # prerender everything into dist/client + the SSR bundle in dist/server, runs the link gate
npm run preview             # serve the built site with the production server on http://localhost:3000 (PORT to change)
npm run typecheck           # generate the route tree, then tsc --noEmit (works on a clean checkout)
npm run check-links         # re-run the link gate on dist/client
node scripts/smoke.mjs http://localhost:3000   # route types, redirects, 404, /healthz, cache headers
node scripts/audit-render.mjs   # structural audit of the rendered HTML (h1s, titles, empty pages)
npm run sync-snippets       # regenerate src/data/snippets.json from the template submodule
npm run sync-registry       # refresh the vendored addon / OpenAPI catalogue (needs network)
node scripts/gen-redirects.mjs  # regenerate legacy /docs/api-reference/* redirect pages and public/_redirects
```

Use Node 22 or newer. `vite dev` is fine for most work; the `/api` SDK explorer is browser-only and is best checked
against `npm run build && npm run preview`.

## Structure

| Path | What lives there |
| --- | --- |
| `content/docs`, `content/blog` | All prose, as `.mdx`. Sidebar order comes from `meta.json` files. |
| `src/routes` | File routes. Marketing pages are thin wrappers around `src/views`; `docs.$` and `blog.*` render content from prerendered JSON payloads. |
| `src/views` | Marketing page bodies (home, developers, features, wires, core, deploy, openapis, addons). |
| `src/components` | Paper-theme kit (`PaperLayout`), MDX components, `site/` (navbar, footer, search, theme toggle, 404). |
| `src/lib` | Content source, payload builders, SEO helpers, search index, catalogue loaders. |
| `src/styles` | Tokens (`--paper-*`), base, prose, shell, docs, animation CSS. |
| `src/data` | Generated and vendored data: `snippets.json`, `surface.json`, catalogue JSON. |
| `packages/vite-link-check` | The prerender link gate. Policy lives in `link-gate.config.mjs`. |
| `plugins` | Build plugins (feeds / sitemap, Shiki themes, remark snippets). |
| `public` | Static assets, `robots.txt`, `_redirects`, legacy redirect pages. |

## Content rules

- **No code in the website.** Every TypeScript example is a snippet from the template project, referenced from MDX as
  ` ```typescript @snippet <id> `. Never hand-write a TS example in a doc, and never edit
  `src/data/snippets.json` by hand.
- Snippets come from the `.template-online-shop` submodule. To change an example: edit it there, push, run
  `npm run sync-snippets`, and commit the submodule bump together with the regenerated JSON.
- AI-generated pages carry `ai: true` in their frontmatter, which shows the disclaimer banner.
- There is no Console. Do not add Console links or docs.
- Deleted pages that must not be linked again: `/pricing`, `/use-cases/*`, `/instant-reload`, `/manual-setup`.

## The link gate

`npm run build` crawls every prerendered page and fails on any internal link or `#anchor` that does not resolve.
`link-gate.config.mjs` is the single place that lists exceptions: server-rendered routes (`ssrRoutes`), pages not yet
ported (`pendingPages`, empty) and ignored patterns.

## Catalogue

`/addons` and `/openapis` are server-rendered from `__data` (generated by `gen:data`; read from disk, `public/__data`
under `vite dev` and `dist/client/__data` in the image). The browse table on `/openapis` loads `/registry-data/openapis.json`, which asks the
hosted registry (`https://api.pikkustudio.app`, override with the `REGISTRY_URL` var) and falls back to the vendored
fixture when it is unreachable.

## Deploy

The site ships as the Docker image `ghcr.io/pikkujs/website` and runs on a Hetzner host behind Caddy, with Cloudflare
as the CDN in front. The origin only has to answer cache misses: static files, the two SSR routes and redirects.

```
browser -> Cloudflare (CDN, caches HTML at the edge) -> Caddy (TLS, gzip) -> container :3000 (server/server.mjs)
```

### What the container does

`server/server.mjs` serves `dist/client` with clean URLs (`/docs/x` -> `docs/x/index.html`, `/docs/x/` redirects to
`/docs/x`), applies `dist/client/_redirects` as 301s (`/fabric`, `/wires/bot`), renders `/addons` and `/openapis`
through the Start SSR handler, returns 404s, and answers `GET /healthz` (200, `no-store`). Settings: `PORT`
(default 3000), `REGISTRY_URL` (default `https://api.pikkustudio.app`). The image has no `node_modules`; the SSR
bundle is self-contained.

Cache headers set by the origin:

| Route type | Cache-Control |
| --- | --- |
| `/assets/*` (hashed) | `public, max-age=31536000, immutable` |
| Prerendered HTML, `/payload/*.json`, `/search-index.json`, sitemap, feeds, redirects | `public, max-age=0, s-maxage=31536000, stale-while-revalidate=86400, stale-if-error=86400` |
| Other static files (images, favicon) | `public, max-age=86400, s-maxage=31536000, stale-while-revalidate=86400, stale-if-error=86400` |
| SSR catalogue (`/addons`, `/openapis`, `/registry-data/openapis.json`) | `public, max-age=0, s-maxage=3600, stale-while-revalidate=86400, stale-if-error=86400` |
| 404 | `public, max-age=0, s-maxage=60` |
| 5xx, `/healthz` | `no-store` |

HTML can sit at the edge for a year because every deploy purges the Cloudflare cache; browsers always revalidate
(`max-age=0` plus ETag).

### Local image

```sh
docker build -t pikku-website .
docker run --rm -p 3000:3000 pikku-website
node scripts/smoke.mjs http://localhost:3000
```

### CI/CD

`.github/workflows/branch.yml` (every branch and PR): sync snippets, typecheck, build (runs the link gate), check
links, and a `docker build` without push. `.github/workflows/main.yml` does the same on `main`, then pushes
`ghcr.io/pikkujs/website:<sha>` and `:latest` (with `GITHUB_TOKEN`), SSHes to the host to pull and restart, and
finally purges the Cloudflare cache.

Repository secrets: `HETZNER_HOST`, `HETZNER_USER`, `HETZNER_SSH_KEY`, `CLOUDFLARE_ZONE_ID`, `CLOUDFLARE_API_TOKEN`
(permission Zone > Cache Purge). The `production` environment can require approval.

### Host setup (once)

1. Install Docker (with the compose plugin) and Caddy. Create the deploy user and add the CI public key to its
   `~/.ssh/authorized_keys`; add the user to the `docker` group.
2. `docker login ghcr.io` as that user with a token that has `read:packages` (or make the package public).
3. `mkdir /opt/pikku-website` and copy `deploy/docker-compose.yml` there. Start it: `docker compose up -d`.
4. Copy `deploy/Caddyfile.example` to `/etc/caddy/Caddyfile`, set up TLS (Cloudflare Origin CA certificate or the DNS
   challenge) and `systemctl reload caddy`.
5. Firewall: allow 80/443 (ideally only from Cloudflare's ranges) and SSH; the container port is bound to 127.0.0.1.
6. Deploys run `cd /opt/pikku-website && docker compose pull && docker compose up -d`. Roll back by setting the image tag
   in `docker-compose.yml` to an earlier `<sha>`.

### Cloudflare setup

- DNS: `pikku.dev` and `www.pikku.dev` as proxied (orange cloud) records pointing at the Hetzner host. SSL/TLS mode
  "Full (strict)".
- Cache Rule: if hostname is `pikku.dev` or `www.pikku.dev` -> Eligible for cache, Edge TTL "Use cache-control header
  if present", Browser TTL "Respect origin". By default Cloudflare does not cache HTML, so this rule is what makes
  the origin see only misses. The origin's `/healthz` is `no-store`, so it is never cached.
- Purge: every deploy calls `purge_everything` on the zone. Targeted purge (by URL or tag) is a later optimisation.
- Redirects (`/fabric`, `/wires/bot`, old URLs) are served by the origin as 301s; no Cloudflare redirect rules needed.

### DNS cutover (pikku.dev)

The site previously deployed to GitHub Pages (`public/CNAME` held `www.pikku.dev`). To cut over:

1. Bring the stack up on the Hetzner host and test it with `curl --resolve pikku.dev:443:<host-ip> https://pikku.dev/healthz`.
2. Create the Cache Rule above, then point the proxied DNS records for `pikku.dev` and `www.pikku.dev` at the host
   (replacing the GitHub Pages `A`/`CNAME` records).
3. Disable GitHub Pages in the repository settings and delete the `CNAME` file if it is still present.
4. Check `/`, `/docs`, `/blog`, `/addons`, `/fabric` (redirects to pikkufabric.com), an old blog URL and a 404;
   `curl -I` a docs page twice and confirm `cf-cache-status: HIT` on the second request.
