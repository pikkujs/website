# PKU585: Duplicate Virtual Users Definition

## Error Message

When the second call is in a different file:

```
[PKU585] Only one defineVirtualUsers(...) is allowed per codebase, so there is one place to read the declarations from and one place to add to. Found a second in src/virtual-users/staff.ts (first: src/virtual-users/customers.ts). Declare them all in one call.
```

When both calls are in the same file:

```
[PKU585] Only one defineVirtualUsers(...) is allowed per codebase, so there is one place to read the declarations from and one place to add to. Found a second call in src/virtual-users/index.ts. Declare them all in one call.
```

## What Went Wrong

`defineVirtualUsers` was called more than once. It's a single-declaration construct: exactly one call per codebase.

`defineVirtualUsers` takes a keyed object, so a single call already declares as many virtual users as you like. Splitting it across calls buys nothing and costs the thing the construct exists for — one place to read the cast from, and one place to add to. The CLI extracts virtual users by AST parsing and generates a `VirtualUserId` union plus a `virtual users.gen.json` that `pikku virtual-user run` reads straight off disk; that only works when there's one authoritative declaration.

A second call in the *same file* is refused too. "The file" isn't an answer to "where do I add a virtual user?" when the file holds two calls.

Generated files (`*.gen.ts`) are exempt and never claim the slot, so a scaffolded `pikku-virtual-users.gen.ts` won't collide with your own declaration.

## How to Fix

Merge every call into one keyed object:

```typescript @snippet defineVirtualUsers
```


Keep the definitions split across files if you like, for example exporting `buyerVirtualUsers` and `staffVirtualUsers` objects, and merge only at the call site with a single `defineVirtualUsers({ ...buyerVirtualUsers, ...staffVirtualUsers })`.

Note that `defineVirtualUsers` is read statically — the spread above works because the CLI can resolve the object literals, but a computed or conditionally-built object cannot be extracted (see [PKU124](/docs/pikku-cli/errors/pku124)).

## Virtual user Best Practices

- Keep the single `defineVirtualUsers` call in a predictable place — `src/virtual-users.ts` — so newcomers find the cast immediately.
- Declare virtual users that only get acted upon (the account an admin bans, the colleague a document is shared with) alongside the ones that run; declaring is not running.
- Use plain object literals; virtual users are parsed, never evaluated.
- Never edit `pikku-virtual-users.gen.ts` — it's regenerated from your declaration.

## Common Mistakes

The broken shape is one `defineVirtualUsers({ susan: ... })` in a buyers file and another `defineVirtualUsers({ marcus: ... })` in a staff file, which leaves two places to look.
