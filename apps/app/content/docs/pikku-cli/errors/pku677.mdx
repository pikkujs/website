# PKU677: Scenario Browser Step Needs Virtual user

## Error Message

```
[PKU677] Scenario 'checkoutFlow' calls step 'searchesAddons', which declares a browser binding, without a virtual user. Pass { virtual user: virtual users.<name> } so the browser context signs in as that virtual user.
```

## What Went Wrong

A scenario calls a step that has a `browser` binding, but the step call has no `{ virtualUser: … }` option.

A browser step drives a real page. Which page — and, crucially, *whose session* — comes entirely from the virtual user: the virtual user is the signed-in virtual user whose browser context the step runs in. Without one there's no session, so the step would open an anonymous browser and the scenario would either fail on a login wall or, worse, quietly exercise the logged-out version of the UI while reading as though it tested the logged-in one.

Non-browser steps can legitimately omit the virtual user; browser steps cannot.

## How to Fix

Pass the virtual user on the step call:


```typescript @snippet scenarioSteps
```

Every browser step in a flow normally takes the same virtual user — that's what makes it one user's story. Switching virtual users mid-flow is legitimate (an admin approving what a buyer submitted) but should be deliberate.

If the virtual user doesn't exist yet, declare the virtual user with `defineVirtualUsers` — virtual users are materialised from virtual users.

### If the step shouldn't be a browser step

A step that only needs to read or write data through the API doesn't need a `browser` binding at all. Give it a plain step body instead, and it can run without a virtual user.

## Scenario Best Practices

- Guard on the virtual user at the top of the flow so a misconfigured run fails with a clear message rather than deep inside a step.
- Keep one virtual user per flow unless the scenario is genuinely about two people interacting.
- Assert through data attributes rather than rendered copy — copy goes through i18n, and reading it back tests your English, not your behaviour.
- Run scenarios with `pikku scenario run <environment>` so virtual users are seeded and signed in.

## Common Mistakes

A browser step called without a virtual user, such as `scenario.when('searches for coffee', 'searchesAddons', { query: 'coffee' })`, has no session to run in.

The fix is to pass `{ virtualUser: virtualUsers.susan }` as the fourth argument of the step call, as in the steps above.
