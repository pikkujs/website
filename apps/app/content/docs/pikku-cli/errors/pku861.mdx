# PKU861: Function Version Modified

## Error Message

`pikku versions update` and `pikku all` report it like this. The recorded value is the input and output hash. The current value is a single hash of both, so the two sides never look alike:

```
[PKU861] Contract for getTodo@v1 has changed (recorded: a1b2c3d4/e5f6a7b8, current: 9f8e7d6c5b4a3210). Existing versions are immutable.
```

`pikku versions check` prints it like this:

```
✗ getTodo@v1 — published contract was modified
  Recorded hash: a1b2c3d4
  Current hash:  9f8e7d6c

  Published versions are immutable. Either revert
  the schema change or create version 2 instead.
```

Those two hashes are of the input schema only. If you changed only the output, they are the same.

## What Went Wrong

The input or output schema of a recorded version no longer matches `versions.pikku.json`. This is the error you get for any such change, whether it is the newest version or an older one, and whether or not the function has a `version` property. A function without one, and with no versioned siblings, is recorded as version 1.

Callers were built against the recorded schemas, so changing them in place can break those callers. Only the schemas are compared. You can change the function body freely.

While this error stands, `versions update` and `pikku all` leave the manifest as it was, including for new functions, and still exit successfully. `versions check` fails, and so does `pikku all --fail-on-error`.

## How to Fix

### If the change was a mistake

Revert it. Look for a shared type or schema: changing one changes every function that uses it.

### If the change is intended

Restore the old schemas and keep that definition as version 1. Put the change in a new definition with the next version, the way `getItem` (version 2) sits beside `getItemV1` here:

```typescript @snippet shopVersionedItem
```

Then record it:

```bash
npx pikku versions update
```

Do not only raise `version` on the existing function. That passes the check and removes the old version from your code.

### If nothing depends on the old schemas yet

`versions update` will not overwrite a recorded version. Before anything is published against it, delete that function's entry from `versions.pikku.json`, run `npx pikku versions update` to record it again, and have the manifest change reviewed. Never do this for a version that callers use, and never edit hashes by hand to make the check pass.
