# PKU862: Contract Changed, Requires Bump

## Error Message

```
[PKU862] Contract for getTodo changed. Set `version: 3` on the function or run 'pikku versions update'.
```

`pikku versions check` prints it like this:

```
✗ getTodo — contract changed without version bump
  Input schema hash:  unknown → a1b2c3d4
  Output schema hash: unknown → e5f6a7b8

  Set `version: 3` on the function, then run:
  npx pikku versions update
```

## What Went Wrong

Despite its name and message, this is not what you get for changing a schema without a new version. That is [PKU861](/docs/pikku-cli/errors/pku861).

PKU862 means `versions.pikku.json` is damaged: a function's `latest` names a version that has no recorded hashes, while your code still has that version. The `unknown` in the output is the missing record. It usually follows a hand edit or a badly resolved merge, and it appears with [PKU863](/docs/pikku-cli/errors/pku863), [PKU865](/docs/pikku-cli/errors/pku865), or both.

## How to Fix

Do not raise `version`, whatever the message suggests. Repair the manifest:

1. Find the commit that last had the function's entry intact, for example with `git log -p versions.pikku.json`.
2. Restore the missing version and its hashes. After a merge, keep the versions from both branches.
3. Check the result:

```bash
npx pikku versions check
```

If the version was never committed, run `npx pikku versions update` to record it. This records the schemas as your code has them now, so first make sure they are the ones callers use.
