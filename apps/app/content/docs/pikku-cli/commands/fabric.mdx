# Fabric

Sign in and deploy to Fabric.

## `pikku login` / `pikku logout` / `pikku whoami`

Authenticate the CLI against a Pikku server (device-authorization flow). Used by commands that talk to a running server.

```bash
npx pikku login                          # Default: http://localhost:3000
npx pikku login --url https://api.example.com
npx pikku login --client-id my-agent --scope "openid profile" --auth-path /auth
npx pikku login --no-open                # Don't open the verification URL in a browser
npx pikku whoami                         # Show the current CLI session
npx pikku whoami --url https://api.example.com
npx pikku logout                         # Remove a stored CLI session
npx pikku logout --url https://api.example.com
```

## `pikku fabric`

The PikkuFabric command group. Most commands take `--branch/-b` to pick the stage and `--api-url` to override the fabric-api URL for one call; `--json` gives machine-readable output where noted. [Deploying with Fabric](/docs/deploy/fabric) covers the workflow; this is the command map.

| Command | What it does |
|---|---|
| `fabric login` | Authenticate against fabric-api. `--api-key`, `--token`, `--api-url`, `--console-url`, `--no-browser` (just print the link) |
| `fabric init <repo>` | Adopt an existing git repo as a fabric project. `--name`, `--branch` (default `main`), `--organization`, `--force` (replace `fabric.config.json`), `--api-url` |
| `fabric link` | Register the current repo as a project and queue an initial deploy. `--github`, `--gitea` (host it on fabric's git server), `--repo-name`, `--organization`, `--api-url` |
| `fabric validate` | Check the project structure for fabric compatibility, with fix hints. `--skip-typecheck` |
| `fabric smoke` | Clean-room smoke test in a temp worktree: install, codegen, migrate, check `pikku dev` starts. `--keep-temp`, `--timeout-seconds`, `--startup-timeout-seconds`, `--port` |
| `fabric status` | Linked project status (active and in-flight deploy) |
| `fabric projects` | Projects in your organization, with ids (works unlinked) |
| `fabric deploy apply [branch]` | Build and deploy a branch or production. `--production`, `--ref`, `--deployment-id`, `--detach`, `--auto-approve/-y`, `--allow-destructive`, `--timeout` (seconds, default 900), `--json` |
| `fabric deploy list` / `units` | Recent deployments / deployed worker units for a branch (`-b`) |
| `fabric rollback <branch> [target]` | Roll live back to a previous artifact. `--list`, `--dry-run`, `--yes/-y` |
| `fabric secrets set\|list\|delete\|rotate` | Stage-scoped secrets. `set <name>` takes `--value` (else prompts or reads stdin) and `--force`; `list` takes `--json`; `delete <name>` and `rotate` take `--force` |
| `fabric variables set\|get <name>` | Stage-scoped variables. `set --value` is read as JSON when it parses; `get --json` |
| `fabric domains list\|add\|remove` | Custom domains for production. `add <hostname> --target api\|app` (default `api`) |
| `fabric db schema` | Live stage database schema (`-b`) |
| `fabric logs` | Stream or fetch logs. `-b`, `--deployment`, `--level`, `--since` (e.g. `15m`), `--follow/-f`, `--json` |
| `fabric metrics` | Request rate, error rate and latency. `-b`, `--hours` (default 24), `--function`, `--json` |
| `fabric trace <traceId>` | Every event for one trace. `-b`, `--json` |
| `fabric errors` | Recent error-level events with trace ids. `-b`, `--function` |
| `fabric addon verify\|publish [dir]` | Check an addon directory is ready, then publish it to the community registry |
| `fabric addon add <id>` | Install a registry addon into `addons/` (`--dir` overrides `addons.addonDir`) |
| `fabric llm key` | Mint or reuse a developer-scoped Fabric AI gateway key. `--shell`, `--env`, `--json` |
| `fabric report [title]` | Report a finding (something about pikku that cost you time). Takes `--kind product\|harness`, `--expected`, `--actual`, `--repro`, `--workaround`, `--proposal`, `--unresolved`, `--stdin` and more; see `pikku fabric report --help` |
| `fabric findings list\|flush\|clear` | Findings held locally because they couldn't be sent: list, send, or discard them |

### `pikku fabric changes`

The todo list filed from inside a deployed stage. Read what's open, file what was decided elsewhere, claim a batch, ask what you need to know, and tick items off.

```bash
npx pikku fabric changes list                         # Open changes, grouped the way they'll be worked
npx pikku fabric changes show --change-id <id>        # One change with its thread and circled elements
npx pikku fabric changes file --title "Group totals" --route /checkout
npx pikku fabric changes claim --change-ids a,b --title "Checkout polish"
npx pikku fabric changes ask --change-id <id> --question "Reprice them?" --option "Reprice" --option "Leave"
npx pikku fabric changes shot --change-id <id> --label "Grouped totals" --image shot.png
npx pikku fabric changes done --change-id <id> --note "Fixed in the totals row"
```

| Subcommand | Options |
|---|---|
| `list` | `--project-id/-p`, `--stage-id`, `--route`, `--group-id`, `--pickup-only`, `--include-done`, `--limit` (default 50, max 200) |
| `show` | `--change-id` |
| `file` | `--project-id/-p`, `--stage-id`, `--branch`, `--title/-t`, `--body`, `--body-file`, `--route`, `--locale` |
| `claim` | `--project-id/-p`, `--group-id`, `--change-ids`, `--title`, `--claimed-by`, `--lease-minutes` (default 30) |
| `ask` | `--change-id`, `--question/-q`, `--option` (repeatable), `--author-name` |
| `shot` | `--change-id`, `--label`, `--image` or `--image-base64`, `--content-type`, `--kind option\|evidence` (default `option`), `--author-name` |
| `done` | `--change-id`, `--branch`, `--head-commit`, `--note`, `--author-name` |

Every `changes` subcommand also accepts `--api-url`.
