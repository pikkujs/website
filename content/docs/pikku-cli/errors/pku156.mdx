# PKU156: Agent Provider Options Unreadable

## Error Message

```
[PKU156] AI agent 'support' has a 'providerOptions' the inspector cannot read statically, so it is missing from the generated metadata. Inline it as an object literal of strings, numbers, booleans, arrays and nested objects.
```

This is a **warning**: the build carries on, but the agent's `providerOptions` are left out of the generated metadata.

## What Went Wrong

`pikkuAgent` takes an optional `providerOptions` object, keyed by provider, that is passed through to the model call. The inspector reads it at build time, without running your code, so it can record it in the agent's metadata.

It can only read a plain object literal. It can't follow a variable, a function call, a spread or a computed value to find out what they hold, so when `providerOptions` is anything other than a literal it gives up on that agent and warns.

## How to Fix

Write the options inline, using only strings, numbers, booleans, arrays and nested objects:

Passing a variable or a function call, such as `providerOptions: buildOptions(process.env.THINKING_BUDGET)`, is what the inspector can't see through. Write an object literal the inspector can read instead:

```typescript @snippet ea-agent-provider-options
```

If a value really has to vary per environment, keep the literal and read the variable inside the function that uses the agent, rather than building the options object itself.
