# PKU642: Workflow Graph Addon Not Wired

## Error Message

```
[PKU642] Workflow graph 'orderPipeline' references 'graph:editFields' but @pikku/addon-graph is not wired. Enable "scaffold": { "graph": true } in pikku.config.json (and install @pikku/addon-graph), or wire it manually with wireAddon({ name: 'graph', package: '@pikku/addon-graph' }).
```

## What Went Wrong

A `pikkuWorkflowGraph` contains a node whose `rpcName` starts with `graph:` — one of the built-in graph primitives such as `graph:editFields`, `graph:map`, or `graph:math` — and `@pikku/addon-graph` isn't wired in this project.

The `graph:*` namespace isn't magic: it's an addon like any other, and its functions only exist once that addon is wired. Without it the RPC never registers, and the failure would otherwise surface much later, deep inside type-checking, as an opaque missing-export error against a name you never wrote by hand. Pikku fails here instead, where the cause is legible.

You'll usually hit this after importing a graph built elsewhere (a shared workflow, an n8n import, a template) into a project that never needed the graph builtins before.

## How to Fix

### Recommended: let the scaffold wire it

Install the addon and turn on the graph scaffold:

```bash
yarn add @pikku/addon-graph
```

```json title="pikku.config.json"
{
  "tsconfig": "./tsconfig.json",
  "srcDirectories": ["src"],
  "outDir": ".pikku",
  "scaffold": {
    "graph": true
  }
}
```

Then regenerate:

```bash
npx pikku prebuild
```

### Or wire it by hand

```typescript @snippet eb-wire-graph-addon
```

The `name` must be exactly `graph` — that's the namespace the `graph:` node references resolve against.

### If you didn't mean to use a builtin


Names without the prefix resolve against your own functions: `graph:editFields` is the builtin (needs `@pikku/addon-graph`), while a bare `editFields` is your own function.

## Workflow Graph Best Practices

- Wire `@pikku/addon-graph` once, in a dedicated wirings file, before importing graphs from elsewhere.
- Remember that a lone pure transform belongs as a `graph:*` builtin rather than as its own single-function addon.
- Build the addon before running codegen in a monorepo — an unbuilt addon contributes no function metadata.
- Re-run `npx pikku prebuild` after adding the wiring; the graph's node references are resolved at generation time.

## Common Mistakes

Wiring the addon under a different namespace, such as `name: 'graphs'`, still leaves `graph:editFields` unresolved.
