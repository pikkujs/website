# PKU864: Version Gap Not Allowed

## Error Message

```
[PKU864] Version 5 for getTodo skips versions. Latest is 3, next must be 4.
```

`pikku versions check` renders it as:

```
✗ getTodo@v5 — version gap detected
  Latest version: 3
  Expected next:  4
  Found:          5

  Versions must be sequential. Set `version: 4`
  on the function.
```

## What Went Wrong

You added a new version of a function whose number skips ahead of the sequence. The manifest records `latest: 3`, so the only valid new version is 4 — you declared 5. Versions form a contiguous history (1, 2, 3, …); gaps would make it ambiguous whether a missing number was never published or was lost, and would break the "next version" arithmetic that tools like `pikku versions update` and the check's own suggestions rely on.

## How to Fix


Jumping from version 3 to `version: 5` is the broken shape.

Set `version` to exactly latest plus one, as the sequential versions below do:

```typescript @snippet shopVersionedItem
```

Then record it:

```bash
npx pikku versions update
```

There's no way to "reserve" numbers — if you want to align versions across functions or with an external API version, do that mapping in your route paths or docs, not in the function version.

## Contract Versioning Best Practices

- Let the tooling pick the number: the [PKU862](/docs/pikku-cli/errors/pku862) message tells you the exact next version when a bump is needed.
- Function versions are an internal contract ledger, not marketing versions — don't try to match them to product releases.
- Bump by one per contract change, even during rapid iteration; re-record instead if nothing shipped yet.
