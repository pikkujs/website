# PKU152: Agent Tool Unknown Namespace

## Error Message

```
[PKU152] AI agent 'support-agent' references tool 'stripe:chargeGet', but no addon is wired under the namespace 'stripe'. Wired namespaces: todos, graph.
```

## What Went Wrong

An agent's `tools` array contains a namespaced reference — `ref('<namespace>:<function>')` — but nothing in the project wires an addon under that namespace.

A namespaced tool is resolved at build time, not at runtime: Pikku looks the namespace up in the addons wired with `wireAddon` so it can type the tool, generate its schema, and hand the model a real description. If the namespace isn't wired there is nothing to resolve against, and shipping the agent anyway would mean the model is offered a tool that can never be called.

The usual cause is a typo in the namespace, or wiring the addon in a file the CLI doesn't scan (check `srcDirectories` in `pikku.config.json`).

## How to Fix

Wire the addon under the namespace the agent uses:

```typescript @snippet ea-addon-namespace
```

The `name` here *is* the namespace. `wireAddon({ name: 'stripe', … })` makes every function the addon exports available as `stripe:<functionName>`.

Then reference it from the agent:

```typescript @snippet ea-agent-addon-tool
```

If the tool is a first-party function in your own project rather than an addon function, drop the namespace entirely:

```typescript @snippet ea-agent-first-party-tool
```

## AI Agent Best Practices

- Read the "Wired namespaces:" list in the error — it is the complete set of prefixes that will resolve.
- Keep addon wiring in one wirings file so the namespace vocabulary is discoverable in a single place.
- Use `ref(...)` rather than a bare string so a renamed function surfaces as a type error before it surfaces as PKU152.
- Build the addon before running codegen — an unbuilt addon contributes no metadata and its functions won't resolve.

## Common Mistakes

Wiring the addon under a different name (`name: 'payments'`) while the agent still references `stripe:chargeGet` causes PKU152. The namespace in the reference has to match the wired name: with `name: 'payments'`, the reference is `ref('payments:chargeGet')`.
