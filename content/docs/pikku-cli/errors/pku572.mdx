# PKU572: Route Query Mismatch

## Error Message

```
[PKU572] Route '/todos' has query parameter(s) [status] not found in function 'listTodos' input type. Input type has: [filter, limit]
```

## What Went Wrong

Your HTTP route declares a query parameter that has no matching property on the wired function's input type. Pikku maps declared query params onto same-named input fields; a name that exists only on the route side would always arrive as `undefined`, so the CLI fails the build instead.

This is the query-string sibling of [PKU571](/docs/pikku-cli/errors/pku571) (path params).

The `query` list is typed against the function's input keys and is valid on POST routes only, where the body is the default home for input.

## How to Fix


In the broken version the input type has a `filter` field, but the route's `query` list names `status`.

The fixed version lists only names that exist on the input type, so `query: ['filter', 'limit']` is valid when the input declares `filter` and `limit`.


Or rename the input property if the query name is the one you want to keep: for `query: ['status']` to pass, the input type needs an optional `status` field.

## HTTP Route Best Practices

- Declare in `query` only fields that exist on the input type — the input type is the contract, the route just maps onto it.
- Make query-mapped fields optional in the input type; query strings are optional by nature.
- One source of truth: when renaming an input field, update every route that maps it.

## Common Mistakes

Pluralisation drift after a refactor is a classic trigger: `query: ['tags']` fails once the input field has become `tag`. Update the route to `query: ['tag']`.
