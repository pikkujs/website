# PKU573: Auth Disabled Requires Sessionless

## Error Message

```
[PKU573] Route '/health' has auth disabled but function 'getStatus' uses pikkuFunc (requires session). Use pikkuSessionlessFunc instead.
```

## What Went Wrong

You wired a function with `auth: false` (directly, or inherited from the route group), but the function itself was created with `pikkuFunc` — which guarantees a session exists and types `session` as always present.

These two declarations contradict each other: with auth disabled, unauthenticated requests reach the function, its session would be `undefined`, and every `session.userId`-style access would blow up at runtime despite the types saying it can't. Pikku refuses the combination at build time.

## How to Fix

### If the route really is public


The broken shape is a function created with `pikkuFunc` (which promises a session) wired on a route with `auth: false`.

Define the function with `pikkuSessionlessFunc`, which types the session as optional:

```typescript @snippet readFunction
```

### If the function really needs a session

Remove `auth: false` from the wiring so the auth middleware runs and the session guarantee holds:


```typescript @snippet sessionFunction
```

## Auth Best Practices

- Choose the function type by contract: `pikkuFunc` = session guaranteed, `pikkuSessionlessFunc` = session optional.
- Watch for inherited `auth: false` on route groups — the error fires even when the individual route doesn't set it.
- In a sessionless function, branch on `session` explicitly when you want optional personalization.

## Common Mistakes

A group-level `auth: false` wrapped around a route whose function is a `pikkuFunc` triggers the same error, even though the individual route never sets it.

Group public routes apart from authenticated ones, so `auth: false` only covers sessionless functions:
