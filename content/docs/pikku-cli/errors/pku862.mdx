# PKU862: Contract Changed, Requires Bump

## Error Message

```
[PKU862] Contract for getTodo changed. Set `version: 3` on the function or run 'pikku versions update'.
```

`pikku versions check` renders it with hash detail:

```
✗ getTodo — contract changed without version bump
  Input schema hash:  a1b2c3d4 → 9f8e7d6c
  Output schema hash: e5f6a7b8 (unchanged)

  Set `version: 3` on the function, then run:
  npx pikku versions-update
```

## What Went Wrong

The **latest** version of a function has a different input or output contract than what `versions.pikku.json` recorded — you changed the function's types/schemas without bumping its version. Consumers (generated clients, other services, published addons) pin themselves to a version's contract; changing it in place would break them without any signal. The check fails so the change becomes an explicit, versioned event.

## How to Fix

### If the change should be a new version (consumers exist)

1. Set the next version on the function:

Set the next version on the function with the `version` property, one higher than the version recorded in the manifest:

```typescript @snippet shopVersionedItem
```

2. Record it in the manifest:

```bash
npx pikku versions update
```

### If nothing depends on the old contract yet

You can accept the in-place change by re-recording the manifest:

```bash
npx pikku versions update
```

This overwrites the recorded hashes for the latest version. Only do this pre-release or when you control every consumer.

## Contract Versioning Best Practices

- Decide the policy per function surface: exposed/public functions always bump; internal ones may re-record while unreleased.
- Watch for indirect contract changes — editing a shared type changes the contract of every function using it.
- Run `pikku versions check` in CI so this error appears in the PR that caused it, with the hash diff in the log.
